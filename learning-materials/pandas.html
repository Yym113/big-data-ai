1. 个人理解（先说人话）

上一节学了 NumPy，它能飞快地算一堆数字。但新闻数据从来不只是数字。 一条评论数据长这样：「这条评论来自微博，发布于 2026-03-01，内容是『终于修好了』，有 158 个赞」。 这里有文字、有日期、有数字混在一起，还有「这条属于哪条报道」的对应关系。

NumPy 数组装不了这种「每一列类型不同」的表格。pandas 就是为这种表格数据而生的。 你可以把它想成「Python 里的 Excel」——但比 Excel 强的地方在于： 它能处理几百万行、能自动化、能写进可复现的脚本。

pandas 只有两个核心对象：

对象是什么类比
Series带标签的一列数据Excel 里的一列（含表头）
DataFrame带行标签和列名的二维表Excel 里的一整个工作表

「带标签」这三个字是 pandas 的灵魂，也是它全部麻烦的来源。 因为一旦有了标签，就出现了三个必须回答的问题：

  1. 你说「第 3 行」，指的是第 3 个位置，还是标签叫 3 的那一行？（→ iloc vs loc）
  2. 你赋值的时候，是按位置对齐，还是按标签对齐？（→ 官方明确说 loc 对齐、iloc 不对齐，结果完全不同）
  3. 你拿到的这一列，是原表的一部分，还是一个独立的副本？（→ 视图 vs 副本，即链式赋值问题的根源）

新手觉得 pandas「玄学」，绝大多数是因为这三个问题没搞清。 本节花最多篇幅的地方也在这里。

还有一个必须提前知道的重大变化：从 pandas 3.0 起，Copy-on-Write 成为默认且唯一的模式。 官方原文是「Copy-on-Write is now the default with pandas 3.0」和「Copy-on-Write is the default and only mode in pandas 3.0」。 这意味着很多老教程里管用的写法现在会失效——第 4.5 节会专门讲。

2. 学习目标

学完这一份，你应该能做到：

  • 能说清 Series 和 DataFrame 的关系，知道索引（index）和列名（columns）的作用。
  • 能区分 loc（按标签）和 iloc（按位置），知道两者对切片边界的处理不同。
  • 能解释为什么 df["A"][条件] = 值 不再生效，并知道正确写法 df.loc[条件, "列"] = 值。
  • 能说出 Copy-on-Write（CoW）解决的是什么问题，以及它带来的三个行为变化。
  • 能说出布尔筛选为什么必须加括号，并知道用 | & ~ 而不是 and or not。
  • 能识别 NaN 与 NA，会用 isna() / notna() 判断，而不是用 ==。
  • 能用 dropna() / fillna() / ffill() / bfill() 处理缺失值，知道整数列出现缺失值后为什么会变成浮点。
  • 知道 inplace 在 CoW 下的争议，能改用「重新赋值」的写法。
  • 会读写 CSV 并记得 encoding 与导出时 index=False。
  • 能用 str.contains(na=False) 做文本筛选，知道 na 参数的默认行为会出问题。

4. 结构化解释

4.1 定义：两个核心对象

pandas 官方对索引（axis labeling）的作用给了三条说明：

The axis labeling information in pandas objects serves many purposes:
  • Identifies data (i.e. provides metadata) using known indicators, important for analysis, visualization, and interactive console display.
  • Enables automatic and explicit data alignment.
  • Allows intuitive getting and setting of subsets of the data set.
——引自 pandas 官方文档《Indexing and selecting data》开头

注意第二条「data alignment」（数据对齐）——这是 pandas 和 NumPy 最本质的区别。 NumPy 只有位置，pandas 有标签。有标签就有「按标签对齐」这件事。

官方还给了一条很重要的建议：

The Python and NumPy indexing operators [] and attribute operator . provide quick and easy access to pandas data structures across a wide range of use cases. ... However, since the type of the data to be accessed isn't known in advance, directly using standard operators has some optimization limits. For production code, we recommended that you take advantage of the optimized pandas data access methods exposed in this chapter. ——引自 pandas 官方文档《Indexing and selecting data》

翻译过来就是：正式代码里请用 .loc / .iloc，少用裸的 [] 和 .属性。 这句话是整份文档里最该记住的一句。

4.2 最小模型：Excel 工作表 + 三种「指路方式」

把 DataFrame 想成一张 Excel 表。你告诉同事「去拿数据」时，可能用三种方式：

你怎么说pandas 里对应注意
「拿『点赞数』这一列」df["点赞数"]返回 Series
「拿行号是 5、列名是『标题』的那个格子」df.loc[5, "标题"]按标签找
「拿第 6 行第 2 列那个格子」df.iloc[5, 1]按位置找（从 0 数）

官方对 loc 与 iloc 的定义：

.loc is primarily label based, but may also be used with a boolean array. .loc will raise KeyError when the items are not found.

.iloc is primarily integer position based (from 0 to length-1 of the axis), but may also be used with a boolean array. .iloc will raise IndexError if a requested indexer is out-of-bounds, except slice indexers which allow out-of-bounds indexing. ——引自 pandas 官方文档《Indexing and selecting data》

这里有个细节非常关键：「.loc will raise KeyError」而「.iloc will raise IndexError」。 报错类型不同，能帮你立刻判断自己用错了哪个。

还有一个容易踩的坑，官方在 loc 的输入类型说明里点出了：

A single label, e.g. 5 or 'a' （注意 5 被解释为索引的标签，不是整数位置） ——引自 pandas 官方文档 .loc 输入类型说明 
# 假设 df 的索引是 ['a', 'b', 'c', ...]
df.loc[5]      # 找「标签叫 5」的那一行，不是「第 5 行」
df.iloc[5]     # 找「第 5 个位置」的那一行（第 6 行）

# 索引是日期时会直接报错（官方示例）
# df.loc[2:3]  →  TypeError: cannot do slice indexing on DatetimeIndex with these indexers [2] of type int

4.3 关键机制一：loc / iloc / []

官方对 [] 返回值类型的说明（表格原文）：

Object TypeSelectionReturn Value Type
Seriesseries[label]scalar value（标量）
DataFrameframe[colname]Series corresponding to colname

另外官方的切片说明也很重要：

With Series, the syntax works exactly as with an ndarray...
With DataFrame, slicing inside of [] slices the rows.

When slicing, both the start bound AND the stop bound are included, if present in the index. Integers are valid labels, but they refer to the label and not the position. ——引自 pandas 官方文档《Indexing and selecting data》

整理成一张对照表：

写法按什么找切片含不含尾越界行为
df.loc[a:b]标签含尾（闭区间）标签不存在 → KeyError
df.iloc[1:4]位置不含尾（同 Python）切片越界不报错，返回空
df.iloc[[4,5,6]]位置列表—任一越界 → IndexError
df[:3]位置（切行）不含尾—

官方对 iloc 越界的说明很具体：

Out of range slice indexes are handled gracefully just as in Python/NumPy.
A single indexer that is out of bounds will raise an IndexError. A list of indexers where any element is out of bounds will raise an IndexError. ——引自 pandas 官方文档《Indexing and selecting data》 
df.iloc[4:10]       # OK，超出部分自动截断
df.iloc[8:10]       # 返回空的 Series，不报错
df.iloc[[4, 5, 6]]  # 如果 6 越界 → IndexError: positional indexers are out-of-bounds

还有一个「带步长的 loc 切片」的陷阱，官方专门说明了：

When using a slice with a step, such as .loc[start:stop:step], note that start and stop are interpreted as labels, while step is applied over the positional index within that label range. This means a stepped slice will behave differently than using the labels range(start, stop, step) when the index is not contiguous integers. ——引自 pandas 官方文档《Indexing and selecting data》 
s = pd.Series(range(10), index=[0, 5, 10, 15, 20, 25, 30, 35, 40, 45])
s.loc[10:50:5]
# 官方输出：
# 10    2
# 35    7
# dtype: int64
# 注意：不是 10, 15, 20...（按标签），而是从标签 10 开始，位置跳 5 步
实践建议：按标签取用 .loc 时，尽量只做「连续区间」的切片。 想要「跳着取」，用 .iloc 更符合直觉。

官方还给出了 loc 切片会失败的两个条件：

However, if at least one of the two is absent and the index is not sorted, an error will be raised (since doing otherwise would be computationally expensive, as well as potentially ambiguous for mixed type indexes).
Also, if the index has duplicate labels and either the start or the stop label is duplicated, an error will be raised. ——引自 pandas 官方文档《Indexing and selecting data》

所以如果你的索引没排序或有重复，loc 切片的行为可能出乎意料。 做分析前先确认索引唯一、必要时 df = df.sort_index()，能省掉很多莫名的报错。

4.4 关键机制二：赋值时的对齐——loc 和 iloc 完全不同

这是本份资料里最「值钱」的一个知识点。官方的两条警告是并列的：

pandas aligns all AXES when setting Series and DataFrame from .loc. This will not modify df because the column alignment is before value assignment. ——引自 pandas 官方文档，.loc 赋值警告
pandas does not align AXES when setting Series and DataFrame from .iloc because .iloc operates by position. This will modify df because the column alignment is not done before value assignment. ——引自 pandas 官方文档，.iloc 赋值警告

官方给的「想交换两列」的例子，最能说明问题：

# ❌ 想交换 A、B 两列的值，但这样写不会成功
df.loc[:, ['B', 'A']] = df[['A', 'B']]
# 值没变！因为 loc 先按列名对齐：把右边 A 列的值放回 A 列，B 放回 B，等于没动

# ✅ 正确的写法：用 .to_numpy() 让右边「没有列名」，只剩位置
df.loc[:, ['B', 'A']] = df[['A', 'B']].to_numpy()

# ✅ 或者用 iloc（按位置，不对齐）
df.iloc[:, [1, 0]] = df[['A', 'B']]

核心结论：loc 会先按标签把两边对齐再赋值；iloc 直接按位置盖上去。 你想「按标签对应」，用 loc；想「按顺序覆盖」，用 iloc。 搞反了会得到静默的错误结果——不报错，但数据是错的。

同类的属性访问陷阱，官方也明确警告了：

You can use attribute access to modify an existing element of a Series or column of a DataFrame, but be careful; if you try to use attribute access to create a new column, it creates a new attribute rather than a new column and will this raise a UserWarning ——引自 pandas 官方文档《Indexing and selecting data》 
# ❌ 不会创建列，而是创建了一个对象属性
df_new.two = [4, 5, 6]
# 打印 df_new 会发现还是只有原来那一列

# ✅ 创建新列的正确形式
df_new['two'] = [4, 5, 6]

官方还列了属性访问的三个限制：

  • 只有索引元素是合法的 Python 标识符时才能用属性访问，比如 s.1 是不允许的。
  • 如果属性名与已有的方法名冲突，该属性不可用，比如 s.min 不行，但 s['min'] 可以。
  • 同理，与 index、major_axis、minor_axis、items 冲突时也不可用。
  • 以上任何一种情况，用标准索引仍然有效：s['1']、s['min']、s['index'] 都能取到对应的元素或列。
——引自 pandas 官方文档《Indexing and selecting data》
简单的实践守则：列名一律用 df['列名']，永远不要用 df.列名。 这一条规则让你一次避开上面所有的坑。

4.5 关键机制三：Copy-on-Write 与链式赋值（重点）

先看官方给出的「旧行为」示例——这就是无数老教程里的写法：

# 旧行为（CoW 之前）
df = pd.DataFrame({"foo": [1, 2, 3], "bar": [4, 5, 6]})
subset = df["foo"]
subset.iloc[0] = 100
df
#    foo  bar
# 0  100    4     ← df 也被改了！
# 1    2    5
# 2    3    6

官方对旧行为的评价：

pandas indexing behavior is tricky to understand. Some operations return views while other return copies. Depending on the result of the operation, mutating one object might accidentally mutate another.
The exact behavior was hard to predict. ——引自 pandas 官方文档《Copy-on-Write (CoW)》

而 CoW 之后，同样的代码：

# CoW 行为
df = pd.DataFrame({"foo": [1, 2, 3], "bar": [4, 5, 6]})
subset = df["foo"]
subset.iloc[0] = 100
df
#    foo  bar
# 0    1    4     ← df 保持不变！
# 1    2    5
# 2    3    6

官方对 CoW 价值的说明：

CoW will lead to more predictable behavior since it is not possible to update more than one object with one statement, e.g. indexing operations or methods won't have side-effects. Additionally, through delaying copies as long as possible, the average performance and memory usage will improve.

CoW means that any DataFrame or Series derived from another in any way always behaves as a copy. As a consequence, we can only change the values of an object through modifying the object itself. CoW disallows updating a DataFrame or a Series that shares data with another DataFrame or Series object inplace. ——引自 pandas 官方文档《Copy-on-Write (CoW)》

翻译成一句话：「从别的对象派生出来的东西，一律当成副本；要改就改它自己。」

CoW 带来的三个必须知道的行为变化（官方列表）：

变化官方原话对你的影响
链式赋值彻底失效 「Chained assignment will never work」 df["A"][条件] = 值 会抛 ChainedAssignmentError 警告。改用 df.loc[条件, "A"] = 值
底层数组变成只读 「Accessing the underlying array of a pandas object will return a read-only view」 df.to_numpy() 返回的数组不能再改；要改先 .copy()，或把 arr.flags.writeable = True（官方说「should be used with caution」）
一次只更新一个对象 「Only one pandas object is updated at once」 取一列单独改（不管是直接改还是用 inplace=True），不再传回父表

关于链式赋值，官方给了完整的对错对比：

# ❌ 链式赋值：两个索引操作连在一起
df["foo"][df["bar"] > 5] = 100
# 会抛 ChainedAssignmentError：它需要同时改视图 df["foo"] 和 df 本身

# ✅ 用 loc 一行完成
df.loc[df["bar"] > 5, "foo"] = 100

关于「取一列单独改」，官方也给了两种改写方式：

# ❌ 对取出来的列用 inplace，不会传回原表
df["foo"].replace(1, 5, inplace=True)
# df 没变

# ✅ 方式一：在整表上操作
df.replace({"foo": {1: 5}}, inplace=True)

# ✅ 方式二（更推荐）：不用 inplace，重新赋值
df["foo"] = df["foo"].replace(1, 5)

官方对 to_numpy() 只读行为的说明：

This array is read-only, which means that it can't be modified inplace: 
>>> arr = df.to_numpy()
>>> arr[0, 0] = 100
ValueError: assignment destination is read-only
The same holds true for a Series, since a Series always consists of a single array. ——引自 pandas 官方文档《Copy-on-Write (CoW)》

官方还提到一个关于构造函数的变化：「The Series and DataFrame constructors now copies a NumPy array by default when not otherwise specified」——这样可以避免你在 pandas 外面改了 NumPy 数组、却把 pandas 对象也改了。 需要省这一次复制时，可以传 copy=False。

最后一个关于性能的官方提醒，很多人会犯：

No defensive copy will be performed if two objects share the same data while you are modifying one object inplace. ... This is not necessary if the initial object df isn't needed anymore. Simply reassigning to the same variable will invalidate the reference that is held by the object.

Creating multiple references keeps unnecessary references alive and thus will hurt performance with Copy-on-Write. ——引自 pandas 官方文档《Copy-on-Write (CoW)》"Patterns to avoid" 节 
# ❌ 保留旧引用，导致改 df2 时触发一次复制
df2 = df.reset_index(drop=True)
df2.iloc[0, 0] = 100

# ✅ 如果 df 不再需要，直接覆盖同名变量，就不触发复制
df = df.reset_index(drop=True)
df.iloc[0, 0] = 100

还有一条关于旧版本的提醒——如果你在网上看到 pd.options.mode.copy_on_write，它是给 pandas 3.0 之前用的：

Copy-on-Write is the default and only mode in pandas 3.0. This means that users need to migrate their code to be compliant with CoW rules.
The default mode in pandas < 3.0 raises warnings for certain cases that will actively change behavior... pandas 2.2 has a warning mode pd.options.mode.copy_on_write = "warn" that will warn for every operation that will change behavior with CoW. ——引自 pandas 官方文档《Copy-on-Write (CoW)》"Migrating to Copy-on-Write" 节
在 pandas 3.0+ 上不需要再设置 pd.options.mode.copy_on_write，CoW 已经是唯一模式。 如果你看到教程里有这一行，说明它写的是 2.x 时代的内容。

4.6 关键机制四：布尔筛选与 where/mask

官方对布尔运算符的说明非常明确：

The operators are: | for or, & for and, and ~ for not. These must be grouped by using parentheses, since by default Python will evaluate an expression such as df['A'] > 2 & df['B'] < 3 as df['A'] > (2 & df['B']) < 3, while the desired evaluation order is (df['A'] > 2) & (df['B'] < 3). ——引自 pandas 官方文档《Indexing and selecting data》 
# ❌ 漏括号：解析成了完全不同的表达式
df[df['A'] > 2 & df['B'] < 3]

# ✅ 每个条件加括号
df[(df['A'] > 2) & (df['B'] < 3)]
df[(df['A'] > 2) | (df['B'] < 3)]
df[~(df['A'] > 2)]
df[df['平台'].isin(['微博', '抖音'])]

loc 与 iloc 在布尔索引上还有一个差异，官方专门警告了：

While loc supports two kinds of boolean indexing, iloc only supports indexing with a boolean array. If the indexer is a boolean Series, an error will be raised. For instance, df.iloc[s.values, 1] is ok. The boolean indexer is an array. But df.iloc[s, 1] would raise ValueError. ——引自 pandas 官方文档《Indexing and selecting data》 
# ✅ loc 可以直接接受布尔 Series
df.loc[s, 'B']

# ⚠️ iloc 只接受布尔数组，不接受布尔 Series
df.iloc[s, 1]          # ❌ ValueError
df.iloc[s.values, 1]   # ✅ 加 .values 转成数组

还有一个非常实用的对比——筛选（改变形状）vs where（保持形状）：

s = pd.Series([-1, 2, -3, 4])

s[s > 0]           # 返回子集：[2, 4]，长度变成 2
s.where(s > 0)     # 保持长度 4：NaN, 2.0, NaN, 4.0，不满足的填 NaN
s.mask(s > 0)      # where 的反操作：只保留不满足的

官方说明 where 的用途是「To guarantee that selection output has the same shape as the original data」， 并提到「mask() is the inverse boolean operation of where」。 什么时候用？当你需要结果与原表行数一致时——比如要按行对齐再参与计算。 官方还提到 where 返回的是「a modified copy of the data」。

另一个实用方法 query()，官方称之为「allows selection using an expression」：

# 普通写法
df[(df['a'] < df['b']) & (df['b'] < df['c'])]

# query 写法：不用重复写 df['...']，而且支持连续比较
df.query('a < b and b < c')
df.query('a < b < c')          # 类数学写法

# 特殊用法：in / not in
df.query('a in b')               # 官方说等价于 df[df['a'].isin(df['b'])]
df.query('a not in b')

官方有一条关于优先级的 Note 要注意：

If the name of your index overlaps with a column name, the column name is given precedence.
（用特殊标识符 index 访问索引，如 df.query('index > 2')） ——引自 pandas 官方文档《Indexing and selecting data》

以及官方的性能说明，很值得记住：

DataFrame.query() using numexpr is slightly faster than Python for large frames. You will only see the performance benefits of using the numexpr engine with DataFrame.query() if your frame has more than approximately 100,000 rows. ——引自 pandas 官方文档《Indexing and selecting data》

也就是说：不到 10 万行，query() 的性能优势不明显，用它主要是为了好读。 别为了性能而用，为了可读性而用。

4.7 关键机制五：缺失值——NaN、NA 与 dtype 变化

官方开头就说明了 pandas 用「不同的哨兵值」表示缺失，取决于数据类型：

pandas uses different sentinel values to represent a missing (also referred to as NA) depending on the data type.
  • numpy.nan for NumPy data types. The disadvantage of using NumPy data types is that the original data type will be coerced to np.float64 or object.
  • NaT for NumPy np.datetime64, np.timedelta64, and PeriodDtype.
  • NA for StringDtype, Int64Dtype (and other bit widths), Float64Dtype (and other bit widths), BooleanDtype and ArrowDtype. These types will maintain the original data type of the data.
——引自 pandas 官方文档《Working with missing data》

官方给的第一个例子就点出了那个最经典的困惑：

>>> pd.Series([1, 2], dtype=np.int64).reindex([0, 1, 2])
0    1.0
1    2.0
2    NaN
dtype: float64       ← 整数列变成 float 了！

为什么会变成 float？因为 NaN 本身是浮点数，整数类型里没有地方放它。 所以一旦整数列里出现缺失值，整列被迫升级成 float64。 布尔列也一样，会变成 object： 

>>> pd.Series([True, False], dtype=np.bool_).reindex([0, 1, 2])
0     True
1    False
2      NaN
dtype: object       ← 布尔列变成 object 了

如果不想让类型被破坏，就要用「可空类型」（nullable dtype，注意首字母大写）：

>>> pd.Series([1, 2], dtype="Int64").reindex([0, 1, 2])
0       1
1       2
2    <NA>
dtype: Int64        ← 保持整数类型！

>>> pd.Series([True, False], dtype="boolean[pyarrow]").reindex([0, 1, 2])
0     True
1    False
2     <NA>
dtype: bool[pyarrow]   ← 保持布尔类型！

注意大写的 "Int64" 和小写的 np.int64 是两种不同的东西。 大写版本支持 <NA>。

判断缺失值用 isna() / notna()：

>>> ser = pd.Series([pd.Timestamp("2020-01-01"), pd.NaT])
>>> pd.isna(ser)
0    False
1     True
dtype: bool

官方还有一条 Note：「isna() or notna() will also consider None a missing value.」

接下来是最重要的一个 Warning：

Equality comparisons between np.nan, NaT, and NA do not act like None 
>>> None == None
True
>>> np.nan == np.nan
False
>>> pd.NaT == pd.NaT
False
>>> pd.NA == pd.NA
<NA>
Therefore, an equality comparison between a DataFrame or Series with one of these missing values does not provide the same information as isna() or notna(). ——引自 pandas 官方文档《Working with missing data》 
# ❌ 用 == 判断缺失值，结果全是 False 或 NA
df[df['列'] == np.nan]        # 永远得不到想要的结果
df[df['列'] == None]          # 也一样

# ✅ 用 isna / notna
df[df['列'].isna()]
df[df['列'].notna()]
df.dropna(subset=['列'])

关于 NA 的传播行为，官方有一段和 np.nan 的对比：

In general, missing values propagate in operations involving NA. When one of the operands is unknown, the outcome of the operation is also unknown. 
>>> pd.NA + 1
<NA>
>>> "a" * pd.NA
<NA>
In equality and comparison operations, NA also propagates. This deviates from the behaviour of np.nan, where comparisons with np.nan always return False. 
>>> pd.NA == 1
<NA>
>>> pd.NA < 2.5
<NA>
To check if a value is equal to NA, use isna() ——引自 pandas 官方文档《Working with missing data》

也有几个「即使有 NA 结果也确定」的特殊情况（官方示例）：

>>> pd.NA ** 0
1
>>> 1 ** pd.NA
1

以及一条关于聚合的重要 Note：

An exception on this basic propagation rule are reductions (such as the mean or the minimum), where pandas defaults to skipping missing values. ——引自 pandas 官方文档《Working with missing data》 
s = pd.Series([1.0, np.nan, 3.0])
s.mean()      # 2.0，NaN 被跳过（注意：这和 NumPy 的 np.mean 行为不同！）
s.sum()       # 4.0

# 想让它不跳过，用 skipna=False
s.sum(skipna=False)   # nan

这一点非常重要：pandas 的 mean() 默认会跳过 NaN，而 NumPy 的 np.mean() 会得到 nan。 所以在 pandas 里你通常不需要 nanmean。

官方对「求和/求积时缺失值当什么」的说明也很实用：

When summing data, NA values or empty data will be treated as zero. 
>>> pd.Series([np.nan]).sum()
np.float64(0.0)
>>> pd.Series([], dtype="float64").sum()
np.float64(0.0)
When taking the product, NA values or empty data will be treated as 1. ——引自 pandas 官方文档《Working with missing data》

以及累积函数的默认行为：

Cumulative methods like cumsum() and cumprod() ignore NA values by default, but preserve them in the resulting array. To override this behaviour and include NA values in the calculation, use skipna=False. 
>>> ser = pd.Series([1, np.nan, 3, np.nan])
>>> ser.cumsum()
0    1.0
1    NaN
2    4.0      ← 3 累加上去的 1，中间的 NaN 被跳过但位置上保留
3    NaN
>>> ser.cumsum(skipna=False)
0    1.0
1    NaN
2    NaN      ← 一旦遇到 NaN，后面全是 NaN
3    NaN
——引自 pandas 官方文档《Working with missing data》

4.8 关键机制六：dropna / fillna

官方对 dropna() 的说明很简洁：「dropna() drops rows or columns with missing data.」

>>> df = pd.DataFrame([[np.nan, 1, 2], [1, 2, np.nan], [1, 2, 3]])
>>> df
     0  1    2
0  NaN  1  2.0
1  1.0  2  NaN
2  1.0  2  3.0

>>> df.dropna()          # 默认丢掉任何含 NaN 的行
     0  1    2
2  1.0  2  3.0

>>> df.dropna(axis=1)     # 按列丢
   1
0  1
1  2
2  2

dropna() 的常用参数（本次来源只展示了 axis，其余为通用 API 用法）：

参数作用典型场景
axis=0（默认）丢行丢掉有缺失的记录
axis=1丢列丢掉缺失太多的字段
how='any'（默认）只要有一个缺失就丢严格清洗
how='all'全部缺失才丢只清理完全空白的行
subset=['列A']只看这几列有没有缺失「标题为空就丢掉」——最常用
thresh=n非缺失值少于 n 个就丢要求「至少填了 3 个字段」
实务提醒：dropna() 会静默删掉数据。 新闻数据里，缺失往往是有意义的（「这条记录字段没填」可能本身就是发现）。 所以标准做法是：先 df.isna().sum() 看每列缺多少，再决定怎么处理，并在方法说明里写清「因缺失删除了 N 条」。 这既是数据质量要求，也是新闻的可核查性要求。

fillna() 的官方定义是：

fillna() replaces NA values with non-NA data. ——引自 pandas 官方文档《Working with missing data》 
>>> df.fillna(0)         # 用标量填充
    np  arrow
0  1.0    1.0
1  0.0    0.0
2  0.0    0.0
3  2.0    2.0

官方对「object 类型下填充值的选择」有一段说明，很细致：

When the data has object dtype, you can control what type of NA values are present. 
>>> df = pd.DataFrame({"a": [pd.NA, np.nan, None]}, dtype=object)
>>> df.fillna(None)      → 全是 None
>>> df.fillna(np.nan)    → 全是 NaN
>>> df.fillna(pd.NA)     → 全是 <NA>
However when the dtype is not object, these will all be replaced with the proper NA value for the dtype. ——引自 pandas 官方文档《Working with missing data》

前向/后向填充（官方原文用词是「Fill gaps forward or backward」）：

>>> df.ffill()      # 用前一个有效值填（forward fill）
    np  arrow
0  1.0    1.0
1  1.0    1.0
2  1.0    1.0
3  2.0    2.0

>>> df.bfill()      # 用后一个有效值填（backward fill）
    np  arrow
0  1.0    1.0
1  2.0    2.0
2  2.0    2.0
3  2.0    2.0

>>> df.ffill(limit=1)    # 最多连续填 1 个
    np  arrow
0  1.0    1.0
1  1.0    1.0
2  NaN   <NA>
3  2.0    2.0

ffill() 在新闻数据里特别常用——比如「日期只在第一行填了，下面几行空着但属于同一天」：

# 原始：日期列只填一次
#   日期        标题
#   2026-03-01  某市启动改造
#   NaN         配套方案公布
#   NaN         居民座谈会召开
#   2026-03-02  第二个议题

df['日期'] = df['日期'].ffill()     # 向下补全
# 这就是官方所说的「Fill gaps forward」

官方还提到可以用「对齐的 Series 或 DataFrame」来填充：

NA values can be replaced with corresponding value from a Series or DataFrame where the index and column aligns between the original object and the filled object. 
>>> dff.fillna(dff.mean())    # 用各列自己的均值填
——引自 pandas 官方文档《Working with missing data》

以及一个等价写法：

DataFrame.where() can also be used to fill NA values. Same result as above. 
>>> dff.where(pd.notna(dff), dff.mean(), axis="columns")
——引自 pandas 官方文档《Working with missing data》

官方还有一条关于 Index 里放缺失值的 Important 提醒：

Even though Index can hold missing values (NaN), it should be avoided if you do not want any unexpected results. For example, some operations exclude missing values implicitly. ——引自 pandas 官方文档《Indexing and selecting data》

4.9 关键机制七：文本筛选与 str.contains

Series.str 是 pandas 给整列字符串做向量化操作的接口，它把上一节学的正则也用上了。 但这里有一个 pandas 特有的坑，和缺失值直接相关。 

import pandas as pd

df = pd.DataFrame({
    "标题": ["某市启动老旧小区改造", "垃圾分类新规实施", None, "地铁新线开通"],
    "来源": ["日报", "晚报", "日报", "电视台"],
})

# ❌ 默认 na 参数会保留 NaN，导致结果是 object 而不是 bool
mask = df["标题"].str.contains("改造")
print(mask)
# 0     True
# 1    False
# 2      NaN      ← 缺失值位置是 NaN，不是 False！
# 3    False
# Name: 标题, dtype: object      ← 注意 dtype 不是 bool

# ✅ 明确指定 na=False：缺失值位置当成 False
mask = df["标题"].str.contains("改造", na=False)
print(mask.dtype)    # bool
print(df[mask])

# ✅ 用正则（记得 r 前缀）
df[df["标题"].str.contains(r"新规|新线", na=False)]

# ✅ 大小写不敏感
df[df["标题"].str.contains("ABC", case=False, na=False)]
这是 pandas 新手最容易被卡住的一处：只要列里有缺失值， 任何 .str.xxx() 的结果都会带上 NaN，dtype 变成 object， 于是筛选时行为不符预期。解法就是统一加 na=False。

其他常用的 .str 方法：

方法作用备注
.str.contains(pat, na=False)是否包含某模式支持正则，返回布尔
.str.startswith(...) / .str.endswith(...)前缀 / 后缀判断同样要 na=False
.str.len()长度统计标题字数
.str.strip()去首尾空白清洗必备
.str.replace(a, b)替换注意默认按正则解释模式
.str.split(pat, expand=True)切分expand=True 拆成多列
.str.extract(r"(\d{4})年")提取分组直接接上一节的正则

顺带一个高频需求：按关键词分组统计，做法是把上一个概念（正则）和这一节结合起来： 

keywords = ["改造", "环保", "交通", "医疗"]

for w in keywords:
    n = df["标题"].str.contains(w, na=False).sum()
    print(f"{w}: {n} 条")

# 也可以一次性建成新列
df["命中词"] = df["标题"].str.extract(rf"({'|'.join(keywords)})", expand=False)

这一节把第 9 份（文件读写）学的内容接到 pandas 上。pandas 让读写变得极简，但有几个固定要写的参数。 

import pandas as pd

df = pd.read_csv(

    na_values=["", "无", "暂无", "N/A"],   # 哪些字符串算缺失

)

# 写出：最常忘的是 index=False
df.to_csv("结果.csv", index=False, encoding="utf-8-sig")

# ✅ 写了 index=False：干净
#    标题,来源,日期

两个固定组合，背下来：
· 读别人给的表：encoding="utf-8-sig"（Excel 另存的 CSV 常带 BOM）

坑 1：链式赋值（CoW 下彻底失效）

# df.loc[1]        # KeyError: 1

# ✅ 按位置取用 iloc

# ✅ 按标签取用 loc
print(df.loc[200])      # 点赞 20

# 记忆：loc → Label（都是 L 开头）；iloc → integer position

print(df.loc[200:300])      # 含 300，2 行

坑 10：整数列因缺失值变成浮点

s = pd.Series([1, 2, 3], dtype="int64")

# ❌ 插入缺失值后 dtype 变成 float64
s2 = s.reindex([0, 1, 2, 3])
print(s2.dtype)         # float64
print(s2.tolist())      # [1.0, 2.0, 3.0, nan]

# ✅ 需要保持整数类型就用可空整数类型（大写 I）
s3 = pd.Series([1, 2, 3], dtype="Int64").reindex([0, 1, 2, 3])
print(s3.dtype)         # Int64
print(s3.tolist())      # [1, 2, 3, <NA>]

# 用 .sum() 看差异
print(s2.sum())         # 6.0
print(s3.sum())         # 6
为什么这件事重要？因为「用户 ID」「条数」这类字段在业务上必须是整数， 一旦被 NaN 变成 1.0 2.0，在输出报告、写进数据库、做键值匹配时都会出问题 （"1" != "1.0"）。发现整数列 dtype 变成 float，第一反应就该是「这一列有缺失值」。

5. 应用场景（新闻传播学）

场景一：把三家平台导出的评论数据清理成统一格式

真实场景：你要做一篇「三个平台评论氛围对比」的报道。 但手上拿到的三份 CSV 出自三个平台，各有各的毛病：

  • 微博导出的：「来源」字段是空的（意思就是微博本身），日期格式是纯数字。
  • 抖音导出的：缺赞数的填了 "-"，标题列里有 "无"。
  • 微信导出的：Excel 另存的，带 BOM，列名前面有看不见的 \ufeff。

这份清理工作要把第 9 份（编码）、第 11 份（正则）和这一节的内容全部用上。

import pandas as pd
import numpy as np

# ---------- 1) 读取：编码 + 缺失值约定 ----------
def read_platform(path, platform):
    """统一读入，把各平台的脏字符串都映射成 NA。"""
    df = pd.read_csv(
        path,
        encoding="utf-8-sig",          # Excel 另存的用这个，带不带 BOM 都能读
        na_values=["", "-", "无", "暂无", "N/A", "null"],   # 各平台占位符统一成 NA
        dtype={"内容": "string"},       # 明确指定文本类型
    )
    # ✅ 关键一步：验证列名有没有 BOM 残留（第 9 份讲过）
    suspicious_cols = [c for c in df.columns if c.startswith("\ufeff")]
    if suspicious_cols:
        print(f"[警告] {platform} 列名有 BOM：{suspicious_cols}")
        df.columns = [c.lstrip("\ufeff") for c in df.columns]

    df["平台"] = platform
    print(f"{platform}: 读入 {len(df)} 条")
    return df

weibo = read_platform("微博.csv", "微博")
douyin = read_platform("抖音.csv", "抖音")
wechat = read_platform("微信.csv", "微信")


# ---------- 2) 合并前先对齐列 ----------
# 平台的列名不统一，需要重命名成同一套
douyin = douyin.rename(columns={"comment": "内容", "like_count": "赞数", "create_time": "日期"})
wechat = wechat.rename(columns={"留言": "内容", "点赞": "赞数", "时间": "日期"})

needed_cols = ["平台", "内容", "赞数", "日期"]
# ✅ reindex 只取需要的列（axis=1 按列）
weibo = weibo.reindex(columns=needed_cols)
douyin = douyin.reindex(columns=needed_cols)
wechat = wechat.reindex(columns=needed_cols)

merged = pd.concat([weibo, douyin, wechat], ignore_index=True)
print(f"\n合并后：{len(merged)} 条")
# ---------- 3) 清理缺失值：先诊断，再处理 ----------
print("--- 各列缺失情况 ---")
missing_counts = merged.isna().sum()
missing_ratios = merged.isna().mean()
for col in merged.columns:
    print(f"  {col}: {missing_counts[col]} 条缺失（{missing_ratios[col]:.1%}）")

# ✅ 处理策略要分开：不同列不能一刀切
before = len(merged)
merged = merged.dropna(subset=["内容"])          # 内容为空的丢掉
print(f"\n因内容为空删除 {before - len(merged)} 条")

# 日期：先尝试前向填充（官方所说的「Fill gaps forward」）
merged["日期"] = merged["日期"].ffill()
# 再处理开头就没有日期的
merged = merged.dropna(subset=["日期"])

# 赞数：用各平台自己的中位数填（比用整体均值更合理）
merged["赞数"] = merged.groupby("平台")["赞数"].transform(
    lambda s: s.fillna(s.median())
)

print(f"清理后剩余缺失单元格：{merged.isna().sum().sum()}")


# ---------- 4) 类型修正 ----------
print(f"\n赞数 dtype：{merged['赞数'].dtype}")
if merged["赞数"].dtype == "float64":
    # ✅ 确认没有小数后再转（避免静默截断）
    if (merged["赞数"] % 1 == 0).all():
        merged["赞数"] = merged["赞数"].astype("int64")
        print("已转为 int64")

merged["日期"] = pd.to_datetime(merged["日期"], errors="coerce")
print(f"日期 dtype：{merged['日期'].dtype}")
# ---------- 5) 分析（用这一节和第 13 份的知识）----------
print("\n=== 平台对比 ===")
summary = merged.groupby("平台").agg(
    条数=("内容", "size"),
    赞数中位数=("赞数", "median"),
    赞数均值=("赞数", "mean"),
    赞数最大=("赞数", "max"),
)
print(summary.round(1))

# ✅ 用布尔筛选找「热评」，注意括号
hot = merged[(merged["赞数"] > 100) & (merged["内容"].str.len() > 20)]
print(f"\n热评（>100 赞 且 >20 字）：{len(hot)} 条")

# ✅ str.contains 一定要 na=False
keywords = ["改造", "环保", "交通", "医疗"]
print("\n--- 关注词命中 ---")
for w in keywords:
    n = merged["内容"].str.contains(w, na=False).sum()
    print(f"  {w}: {n} 条")

# ---------- 6) 导出交付文件 ----------
merged.to_csv("三平台评论_已清理.csv", index=False, encoding="utf-8-sig")
print("\n已导出（Excel 双击打开不乱码）")

这段代码几乎用上了这一节所有的关键点：

  • 读的时候就把噪声定义清楚：na_values 把各平台的占位符一次性映射成 NA，比读进来再一条条 replace 干净得多。
  • BOM 检查：用 startswith("\ufeff") 主动检查列名，不靠运气。
  • 缺失值分策略：dropna(subset=["内容"]) 删关键字段缺失的；ffill() 补可推导的；groupby + transform + fillna 分平台填统计值。
  • 类型修正：主动检查「本来是整数、因 NaN 变成 float」的情况，并先确认没有小数再转。
  • 布尔筛选取括号、str.contains 带 na=False：这两个是高频错误点。
  • 导出带 index=False, encoding="utf-8-sig"：直接可以发给同事用 Excel 打开。

还有一处值得留意：transform 与 agg 的区别。 agg 把每组压成一个数（结果变短）； transform 保持原行数（每行填上它所属组的统计值）。 「填缺失值」必须用 transform，因为它要返回和原表一样长的一列。

场景二：做一份可复现的「报道影响力周报」底表

真实场景：每周要出一份周报，底表包含「每篇报道的阅读量、转发量、评论量、标题字数、是否命中本周关注议题」。 主任最在意的是「可复现」——同一份原始数据跑脚本能得到同一份底表， 而且每个数字都能解释「怎么算出来的」。

这就是 pandas 相对 Excel 的核心优势，也是 CoW 时代写法最讲究的地方。

import pandas as pd
import numpy as np

# 一列一列地算，每一步都写成「明确赋值」：不用 inplace，不链式赋值
# 这样每一步都能单独打印检查，而且完全符合 CoW 规则

df = pd.DataFrame({
    "标题": ["某市启动老旧小区改造", "垃圾分类新规实施首月观察",
             "地铁新线开通首日客流", "社区医院夜间门诊调查", None],
    "阅读量": [12000, 8500, 25000, 6300, 9000],
    "转发量": [120, np.nan, 800, 45, 60],
    "评论量": [88, 40, 320, 12, np.nan],
})

# ---------- 步骤 0：清洗前先记录基线（可核查性要求）----------
baseline = {
    "原始条数": len(df),
    "缺失单元格数": int(df.isna().sum().sum()),
}
print("清洗前基线：", baseline)

# ---------- 步骤 1：丢掉标题缺失的行，并记录影响 ----------
before = len(df)
df = df.dropna(subset=["标题"]).copy()      # ✅ 明确 .copy()，避免后续连带
print(f"因标题缺失删除了 {before - len(df)} 条")

# ---------- 步骤 2：填充互动量缺失，用中位数并注明 ----------
df["转发量"] = df["转发量"].fillna(df["转发量"].median())
df["评论量"] = df["评论量"].fillna(df["评论量"].median())

# ---------- 步骤 3：派生列，一列一行，都是明确赋值 ----------
df["标题字数"] = df["标题"].str.len()

# ✅ 用 loc 做条件赋值（CoW 唯一正确的写法）
df.loc[df["标题字数"] > 12, "标题长度档"] = "长标题"
df.loc[df["标题字数"] <= 12, "标题长度档"] = "短标题"
df["标题长度档"] = df["标题长度档"].fillna("未知")    # 兜底

# ✅ 派生「互动总量」
df["互动总量"] = df["转发量"] + df["评论量"]

# ✅ 派生「互动率」，注意防除零
safe_denom = df["阅读量"].replace(0, np.nan)
df["互动率"] = (df["互动总量"] / safe_denom).round(4)

# ✅ 关注议题命中（str.contains 用 na=False）
topics = ["改造", "环保", "交通", "医疗", "教育"]
df["命中议题"] = df["标题"].str.extract(rf"({'|'.join(topics)})", expand=False)
df["是否关注议题"] = df["标题"].str.contains("|".join(topics), na=False)

# ✅ 是否热文：两个条件必须加括号，并且只能用 loc 赋值
df.loc[(df["阅读量"] > 10000) & (df["互动率"] > 0.01), "是否热文"] = "是"
df["是否热文"] = df["是否热文"].fillna("否")

# ---------- 步骤 4：输出可交付的底表 ----------
print("\n=== 周报底表 ===")
output_cols = ["标题", "阅读量", "转发量", "评论量", "标题字数",
               "互动总量", "互动率", "命中议题", "是否关注议题", "是否热文"]
print(df[output_cols].to_markdown(index=False))

# ---------- 步骤 5：汇总 + 全程可追溯 ----------
print("\n=== 汇总 ===")
print(f"纳入报道：{len(df)} 条（原始 {baseline['原始条数']} 条）")
print(f"命中关注议题：{df['是否关注议题'].sum()} 条")
print(f"判定为热文：{(df['是否热文'] == '是').sum()} 条")
print(f"互动率中位数：{df['互动率'].median():.4f}")

# ---------- 步骤 6：导出 ----------
df[output_cols].to_csv("周报底表.csv", index=False, encoding="utf-8-sig")

这份脚本的设计思路值得完整理解：

  • 每一步都是「明确赋值 + 可打印」：df["新列"] = ... 或 df.loc[条件, "列"] = ...。 没有一处 inplace=True，没有一处链式赋值。这是 CoW 时代的推荐写法，也是最好调试的写法。
  • 删数据要记账：baseline["原始条数"] 和删除条数都打印出来。写进方法说明里，就是可核查性的体现。
  • 条件赋值用两次 loc 覆盖所有情况，再 fillna 兜底：比 if-elif 逻辑清楚，也不会漏掉分类。
  • 防除零：.replace(0, np.nan) 把 0 换成 NaN，避免 inf 污染。
  • str.extract + str.contains：一个拿命中词，一个拿布尔标志，都要 na=False。
  • 主动导出「口径说明」：这不是技术要求，是新闻工作的职业要求——每个数字都要能解释怎么来的。

6. 概念辨析

辨析 1：loc vs iloc

df = pd.DataFrame({"值": [10, 20, 30]}, index=[5, 6, 7])

df.loc[6]       # 找「标签是 6」的行 → 值 20
df.iloc[6]      # ❌ IndexError: 位置 6 越界（只有 0,1,2 三个位置）
df.iloc[1]      # 位置 1（第 2 行）→ 值 20

# 切片语义不同
df.loc[5:7]     # 含 7，3 行（标签闭区间）
df.iloc[0:2]    # 不含 2，2 行（同 Python）

官方对 loc 的说明：「A single label, e.g. 5 or 'a' （注意 5 被解释为索引的标签，不是整数位置）」； 对 iloc 的说明：「primarily integer position based (from 0 to length-1)」。 记忆口诀：loc 的 L = Label；iloc 的 i = integer position。

辨析 2：df["A"][条件] = 值 vs df.loc[条件, "A"] = 值

df = pd.DataFrame({"A": [1, 2, 3], "B": [4, 5, 6]})

# ❌ 链式赋值：CoW 下抛 ChainedAssignmentError，而且不生效
df["A"][df["B"] > 5] = 100

# ✅ 单次 loc 操作
df.loc[df["B"] > 5, "A"] = 100

官方原话：「Chained assignment references a technique where an object is updated through two subsequent indexing operations」， 而 CoW 下「chained assignment will consistently never work and raise a ChainedAssignmentError warning」。 原因是它要同时改视图 df["foo"] 和 df， 而 CoW 明确禁止「一次更新多于一个对象」。 记住这个替换：[列][条件] = 值 → .loc[条件, 列] = 值。

辨析 3：loc 对齐 vs iloc 不对齐

df = pd.DataFrame({"A": [1, 2], "B": [3, 4]})

# loc：按列名对齐 → 想交换却等于没换
df.loc[:, ["B", "A"]] = df[["A", "B"]]
#   A  B
# 0 1  3     没变

# 用 to_numpy 去掉标签
df = pd.DataFrame({"A": [1, 2], "B": [3, 4]})
df.loc[:, ["B", "A"]] = df[["A", "B"]].to_numpy()
#   A  B
# 0 3  1     换过来了

# iloc：按位置，直接盖
df = pd.DataFrame({"A": [1, 2], "B": [3, 4]})
df.iloc[:, [1, 0]] = df[["A", "B"]]
# 也会换过来

官方两条警告是并列的：loc「aligns all AXES」，iloc「does not align AXES」。 这个差异不报错，但结果完全不同——所以它比报错更危险。 判断方法是问自己：「我是想让值按标签找到对应位置，还是想按顺序铺上去？」

辨析 4：筛选（改变形状）vs where（保持形状）

s = pd.Series([-1, 2, -3, 4])

s[s > 0]            # [2, 4]，长度 2  ← 筛选
s.where(s > 0)      # NaN, 2.0, NaN, 4.0，长度 4  ← 保持形状
s.mask(s > 0)       # -1.0, NaN, -3.0, NaN  ← where 的反操作

官方说明 where 的用途是「To guarantee that selection output has the same shape as the original data」， 并提到「mask() is the inverse boolean operation of where」。 什么时候用？当你需要结果和原表行数一致时—— 比如要把它当成另一列参与运算，或者要塞回原表而不引起对齐问题。

辨析 5：NaN vs None vs NaT vs NA

# float 列 → NaN
pd.Series([1.0, np.nan]).dtype          # float64

# object 列 → 保留你放进去的东西
pd.Series([1, None], dtype=object)      # 显示 None

# 时间列 → NaT
pd.Series([pd.Timestamp("2020-01-01"), pd.NaT]).dtype   # datetime64[us]

# 可空整数列 → NA
pd.Series([1, pd.NA], dtype="Int64")    # 显示 <NA>

# 判断：统一用 isna()，它会把 None 也算进去
# 官方 Note：「isna() or notna() will also consider None a missing value.」

官方的分类是：numpy.nan 用于 NumPy 类型（缺点是「the original data type will be coerced to np.float64 or object」）； NaT 用于时间类型；NA 用于可空类型（「These types will maintain the original data type of the data」）。 实践结论：判断一律用 isna()，不用关心具体是哪一个。

辨析 6：inplace=True 还该不该用

df = pd.DataFrame({"A": [1, 2, 3]})

# ❌ 在 CoW 下经常失效（尤其是对取出来的列操作时）
df["A"].replace(1, 100, inplace=True)     # 不生效

# ✅ 官方推荐：不用 inplace，重新赋值
df["A"] = df["A"].replace(1, 100)

# ✅ 或者用整表形式操作
df.replace({"A": {1: 100}}, inplace=True)

官方在 CoW 文档里明确给出两种改写方式，并说明「A different alternative would be to not use inplace」。 加上 CoW 的核心原则「we can only change the values of an object through modifying the object itself」， 实践建议很明确：默认不用 inplace，统一写 df = df.method(...) 或 df["列"] = ...。 好处是：① CoW 兼容；② 链式调用友好；③ 出错时容易回退（原始对象还在）。

7. 自测问题

Q1：为什么 df["点赞"][df["来源"] == "微博"] = 0 不生效了？正确写法是什么？
因为这是链式赋值——两个后续的索引操作。df["点赞"] 先返回一个派生对象， 再对它做布尔索引赋值，就变成了「一条语句要同时更新两个对象」。 CoW 规则明确禁止这一点，官方原话是「CoW disallows updating a DataFrame or a Series that shares data with another DataFrame or Series object inplace」， 并说「chained assignment will consistently never work and raise a ChainedAssignmentError warning」。 正确写法是把两次索引合并成一次 loc： df.loc[df["来源"] == "微博", "点赞"] = 0。
Q2：df.loc[:, ["B","A"]] = df[["A","B"]] 为什么没有交换两列？
因为官方明确说「pandas aligns all AXES when setting Series and DataFrame from .loc」。 赋值前会先按列名把右边对齐到左边：右边的 A 列被放到左边的 A 列位置， B 放到 B 位置，等于原样放回，所以看不出变化。 官方给出的解法是加 .to_numpy()：df.loc[:, ["B","A"]] = df[["A","B"]].to_numpy()， 这样右边没有列名只剩位置，就会按顺序盖上去。 对比之下 iloc「does not align AXES」，所以 df.iloc[:, [1,0]] = df[["A","B"]] 也能交换成功。
Q3：为什么布尔筛选必须写 df[(df["A"] > 2) & (df["B"] < 3)]，不能写成 df[df["A"] > 2 & df["B"] < 3]？
因为运算符优先级。& 的优先级比比较运算符高，所以不加括号时 Python 会把 df["A"] > 2 & df["B"] < 3 解析成 df["A"] > (2 & df["B"]) < 3——这跟你想的完全不同。 官方原文就是拿这个表达式举例的：「by default Python will evaluate an expression such as df['A'] > 2 & df['B'] < 3 as df['A'] > (2 & df['B']) < 3」， 而「the desired evaluation order is (df['A'] > 2) & (df['B'] < 3)」。 另外组合多条件必须用 & / | / ~，不能用 and / or / not。
Q4：为什么不能用 df[df["列"] == np.nan] 找缺失值？该用什么？
因为 np.nan == np.nan 的结果是 False——官方在 Warning 里明确对比了： None == None 是 True，而 np.nan == np.nan 是 False， pd.NaT == pd.NaT 是 False，pd.NA == pd.NA 得到 <NA>。 所以「用等号比较缺失值」根本得不到想要的结果，永远返回空。 正确做法是用 df[df["列"].isna()] 或 df.dropna(subset=["列"])。 官方还有一条 Note：isna() 也会把 None 视为缺失值，所以它是最通用可靠的判断方法。
Q5：一个原本是 int64 的「条数」列，插入一个缺失值后 dtype 变成了 float64。为什么？怎么避免？
因为用的是 NumPy 类型，而 NaN 本身是浮点数，整数类型里没有位置存它。 官方对 numpy.nan 的说明就直接点出了这个缺点： 「The disadvantage of using NumPy data types is that the original data type will be coerced to np.float64 or object」。 避免方法是改用可空类型（注意大写）：pd.Series([1,2,3], dtype="Int64")， 官方说这类类型「will maintain the original data type of the data」，缺失值会显示为 <NA> 而不是 NaN。 布尔列同理，boolean[pyarrow] 能保持布尔类型，而 np.bool_ 会变成 object。
Q6：df["标题"].str.contains("改造") 在标题列有缺失值时会出现什么后果？怎么修？
缺失值位置的结果是 NaN 而不是 False， 所以整个结果列的 dtype 会变成 object 而不是 bool， 拿去做索引时行为与预期不符甚至报错。 修法是加 na=False：df["标题"].str.contains("改造", na=False)， 这样缺失值位置被当成 False，结果 dtype 是干净的 bool。 所有 .str.xxx() 方法都有这个问题，建议养成「凡是用 .str 就顺手写 na=False」的习惯。
Q7：to_csv() 为什么一定要加 index=False？还有哪个参数对交付很关键？
因为 DataFrame 的行索引默认会被当成一列写出去，导出的 CSV 第一列是一个没有表头的行号： ,标题,来源 / 0,A,日报。 别人用 Excel 打开时会看到「多了一列没有名字的列」，导入别的系统时也会多出一个字段。 index=False 就是告诉 pandas「不要写行索引」。 另一个关键参数是 encoding="utf-8-sig"——第 9 份讲过，Excel 另存或双击打开 UTF-8 的 CSV 容易乱码， 加 BOM 能让 Excel 正确识别。 所以交付 CSV 的固定组合是：df.to_csv(path, index=False, encoding="utf-8-sig")。
