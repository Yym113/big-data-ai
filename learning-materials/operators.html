1 · 个人理解（先说人话）

上一份资料说：变量是名字，类型是形状。那运算符是什么？ 运算符是你对盒子里的东西下的指令 —— 是动词。 

total = 12 + 30
#         ↑ 这就是运算符：告诉 Python「把这两个数加起来」

但运算符最反直觉的一点是：同一个符号，遇到不同的类型，干的是完全不同的事。 

12 + 30        # 42        两个数字 → 加法
"12" + "30"    # "1230"    两个字符串 → 拼接，不是加法
[1, 2] + [3]   # [1, 2, 3] 两个列表 → 接成一串

# 同理，* 也不只是乘法：
3 * 4          # 12         数字 × 数字 → 乘法
"ab" * 3       # "ababab"   字符串 × 整数 → 重复三次
一句话记住：运算符是给数据下的指令，结果由两边数据的类型决定。 所以「这个符号是什么意思」这个问题，永远要先回答「它两边的数据是什么类型」。 这也是为什么第 1 份资料要先讲类型 —— 不讲类型，运算符根本没法讲。

还有一条贯穿全程的规则：运算符有先后顺序，不确定就用括号。 官方教程专门为这件事加了一条脚注：** 比 - 优先级更高，所以 -3**2 会被解释成 -(3**2)，结果是 -9； 想要 9 就得写 (-3)**2。这不是冷知识，是新手必然会踩的坑。

2 · 学习目标

学完这份资料，你应该能：

  1. 说出 Python 运算符的七大类，并各自举一个例子；
  2. 解释 / 与 // 的区别，并准确预测 17/3、17//3、-7//2、-7%2 的结果；
  3. 解释为什么 and / or 返回的是操作数本身而不是 True / False，并会用 s or "默认值" 兜底；
  4. 区分 == 与 is，并说出判断 None 时该用哪个；
  5. 看懂官方优先级表，并养成「拿不准就加括号」的习惯；
  6. 按 PEP 8 的要求正确书写运算符两侧的空格；
  7. 知道位运算符是干什么的，以及为什么现阶段可以先放着不深入。

4 · 结构化解释

4.1 定义

运算符（operator）：用来对一个或多个「操作数（operand）」执行某种运算的符号。 在 Python 中，运算符对操作数做什么，由操作数的类型决定 —— 同一个符号挂到不同类型上，可以调用完全不同的实现。

这也是 Python 官方给出的算术转换规则的由来：官方文档在 +、-、*、/、//、% 的说明里都反复写着 「数字参数被转换为通用类型」（numeric arguments are first converted to a common type）， 而 + 单独补了一句：参数「要么都是数字，要么都是同类型的序列」，前者相加、后者拼接。

4.2 最小模型：一条表达式怎么被算出来

result = "reads: " + str(12800)

# 1. 先看优先级：str(...) 是函数调用，最高优先级，先算 → "12800"
# 2. 现在两边都是 str，+ 选择「拼接」这条实现 → "reads: 12800"
# 3. 赋值符 = 把结果贴到名字 result 上

bad = "reads: " + 12800
# TypeError: can only concatenate str (not "int") to str
# ↑ 同一个 + ，左边是 str 右边是 int，找不到能同时处理两者的实现 → 报错
关键点：运算符没有「通用含义」，只有「针对某类型的含义」。 报 TypeError 时，本质上不是运算符坏了，而是你让它处理了一对它不认识的类型组合。

4.5 算术运算符：真正需要理解的部分

（1）/ 与 //：为什么要有两个除法

17 / 3    # 5.666666666666667   ← 除法运算总是返回浮点数
17 // 3   # 5                    ← 向下取整除法，丢弃小数部分
17 % 3    # 2                    ← 取余
5 * 3 + 2 # 17                   ← 官方用这行说明三者关系

官方教程的原话是：「除法运算（/）总是返回浮点数」。 想要整数结果就用 //；要余数用 %。

// 的名字容易骗人：它不是「截断小数」，而是向下取整（floor，朝负无穷方向）。 官方文档给了四组对照：

表达式结果为什么
1 // 200.5 向下取整
(-1) // 2-1-0.5 向下取整 → 更小的整数
1 // (-2)-1-0.5 向下取整
(-1) // (-2)00.5 向下取整
新手必踩：负数整除。-7 // 2 的结果是 -4（不是 -3），因为 -3.5 向下取整到 -4。 想验证就记住官方给的恒等式：x == (x // y) * y + (x % y)，以及 divmod(x, y) == (x // y, x % y)。

（2）%：结果的符号跟着除数走

官方原文：「取模运算符的结果符号总是与第二个操作数相同（或为零）」， 并且结果的绝对值严格小于第二个操作数的绝对值。所以 -7 % 2 是 1，而 7 % -2 是 -1。

实际用途（比「求余数」这个说法有用得多）：

# 判奇偶：偶数对 2 取余为 0
count = 7
if count % 2 == 0:
    print("even")
else:
    print("odd")

# 周期循环：第 i 条数据分到 7 个桶里的哪一个
bucket = i % 7

# 补零显示：把 3 显示成 003
label = str(3).zfill(3)   # 这也是「字符串格式化」的用法，见第 2 份资料

（3）**：右结合，且与一元符号有坑

官方优先级表注写明：「相同单元格内的运算符从左至右组合（只有幂运算符和条件表达式是从右至左组合的）」。 所以 2 ** 3 ** 2 等于 2 ** 9 = 512，而不是 8 ** 2 = 64。 

10 ** 2     # 100     整数底数与正整数指数 → int
10 ** -2    # 0.01    指数为负 → 结果转为 float
2 ** -1     # 0.5     幂运算符绑定（比其右侧的一元运算符）松，所以是 2 ** (-1)
-3 ** 2     # -9      等价于 -(3**2)，不是 (-3)**2
(-3) ** 2   # 9       想要 9 就得这么写

其他官方给出的边界：0 ** 0 定义为 1；对 0.0 取负幂会抛 ZeroDivisionError；对负数取分数幂会返回 complex。

（4）当 + 和 * 遇到序列

官方原文：+ 的两个参数「要么都是数字，要么都是同类型的序列」——后者执行拼接。 * 则允许「一个是整数、另一个是序列」，此时执行重复；负数重复次数会得到空序列。 

3 * "un" + "ium"          # 'unununium'        官方教程原例
[1, 4, 9] + [16, 25]      # [1, 4, 9, 16, 25]  列表拼接
"ab" * 0                  # ''                 重复 0 次
"ab" * -1                 # ''                 负数视为 0
经典陷阱：[[]] * 3。 官方文档专门用一段警告这件事：[[]] * 3 得到的是三个指向同一个空列表的引用， 所以 lists[0].append(3) 之后整个 lists 会变成 [[3], [3], [3]]。 正确做法是用推导式：[[] for i in range(3)]。

（5）混合类型的算术：窄的变宽的

4 * 3.75 - 1   # 14.0   官方教程原例：混合类型运算会把整数转换为浮点数
1 + 1.0        # 2.0
"1" + 1        # TypeError: can only concatenate str (not "int") to str

官方「内置类型」章节的原话是：当二元算术运算符的两个操作数是不同的内置数值类型时， 「较窄」的类型会被拓宽到另一个的类型。但注意 —— 这条规则只对数值类型成立，跟字符串没关系。

4.6 逻辑运算符：and / or 返回的不是布尔值

这是本文最重要的一个认知纠正。官方原文（语言参考 6.11 布尔运算）：

「表达式 x and y 首先对 x 求值；如果 x 为假则返回该值；否则对 y 求值并返回其结果值。」
「表达式 x or y 首先对 x 求值；如果 x 为真则返回该值；否则对 y 求值并返回其结果值。」
「请注意 and 和 or 都不限制其返回的值和类型必须为 False 和 True，而是返回最后被求值的操作数。」 
"a" or "b"      # 'a'      左边为真 → 直接返回左边
"" or "b"       # 'b'      左边为假 → 返回右边
[] and "x"      # []       左边为假 → 短路，返回左边
"y" and "x"     # 'x'      左边为真 → 返回右边
not ""          # True     只有 not 一定返回布尔值
not "foo"       # False    官方特别指出：不是返回 '' 而是 False

官方还给出了这么设计的理由：假设 s 是一个「当其为空时应被替换为默认值」的字符串， 那么 s or "foo" 就能得到想要的结果。这就是它最常用的实战场景（见第 5 节）。

另外，「假值」的完整清单也是官方定义的：False、None、任何数值零、以及空字符串和空容器。 其余一切都是真值。

4.7 比较运算符：可以串起来写

官方原文：「a op1 b op2 c ... y opN z 就等价于 a op1 b and b op2 c and ... y opN z， 不同点在于每个表达式最多只被求值一次。」 

x = 3
0 < x <= 5      # True    等价于 0 < x and x <= 5，但 x 只求值一次
0 < x > 2       # True    合法！但注意：它不表示 x 与 2 之外还比较了 0 和 2

# 官方原话：「a op1 b op2 c 不意味着在 a 和 c 之间进行任何比较」
# 所以 x < y > z 是完全合法的写法，也不代表 x < z。

4.8 is 与 ==：比的是两个不同的东西

写法比较的是什么类比
a == b值是否相等（调用 __eq__，内置类型按值比）两个盒子里的东西是不是一样
a is b是不是同一个对象（等价于 id(a) == id(b)）是不是同一个盒子本身
 
a = [1, 2]
b = [1, 2]
a == b     # True    值一样
a is b     # False   是两个不同的列表对象

x = None
x is None  # True    ← 这才是判断 None 的标准写法
a is not b # True

官方 FAQ 的结论很干脆：「其他大多数情况下，都不建议使用身份相等性测试，而应采用相等性测试。」 官方文档还补充：is / is not 的行为无法被自定义，可以作用于任意两个对象且永不抛异常。

4.10 增强赋值：+= 是简写，但不完全等同

n = 1
n += 1        # 等价于 n = n + 1

对数字而言两者没差别。但对可变序列，官方文档写明 s += t 的效果是 「用 t 的内容扩展 s」（基本等同于 s[len(s):len(s)] = t）—— 也就是就地修改原对象， 而不是造一个新列表。这个差别在「两个变量指向同一个列表」时会显形，属于第 3 份《列表》的坑，这里先知道有这么回事。

另外 *= 对序列也成立，官方注明：零和负数会清空序列。

4.11 位运算符：知道是什么，暂时不用深挖

官方定义：位运算只对整数有意义，结果「如同在具有无限多个符号位的二进制补码中执行」。 优先级上，二元位运算低于数值运算、高于比较运算；一元 ~ 与 + / - 同优先级。

运算结果官方备注
x & y按位与—
x | y按位或—
x ^ y按位异或—
x << n左移 n 位等价于乘以 pow(2, n)；负移位计数会抛 ValueError
x >> n右移 n 位等价于整除 pow(2, n)
~x按位取反—
一个官方明确的坑：不要把 & / | / ^ 当逻辑运算符用。 官方原文说得很直接：对两个布尔值用 & / | / ^ 确实能得到等价结果， 但「应优先使用逻辑运算符 and、or 和 !=」。 原因之一是它们不短路：x != 0 and 1/x > 1 是安全的，写成 & 就可能在 x 为 0 时直接除零。 另一个明确的信号：官方已标注自 3.12 起对布尔值使用 ~ 的写法被弃用，并将在 3.16 报错。

现阶段的态度：知道 & / | / ^ / << / >> 存在、能读懂； 在自己写业务代码时用 and / or 表达条件即可。

4.12 书写规范：PEP 8 怎么说

PEP 8 的原文规定：

「总是在这些二元运算符的两侧各用一个空格：赋值（=）、增强赋值（+=、-= 等）、 比较（==、<、>、!=、<=、>=、in、not in、is、is not）、 布尔（and、or、not）。」

而当不同优先级的运算符混用时，PEP 8 建议只在优先级较低的那些运算符周围加空格：

# 正确（PEP 8 原例）
i = i + 1
submitted += 1
x = x*2 - 1
hypot2 = x*x + y*y
c = (a+b) * (a-b)

# 错误（PEP 8 原例）
i=i+1
submitted +=1
x = x * 2 - 1
hypot2 = x * x + y * y
c = (a + b) * (a - b)
这条规则有个例外，也是新手最容易搞错的一处： 「不要在用于指示关键字参数或未标注类型的函数默认值时为 = 加空格」，但 「当默认值带类型注解时，则要给 = 加空格」。 
# 正确
def complex(real, imag=0.0):
    return magic(r=real, i=imag)

def munge(sep: AnyStr = None): ...          # 带注解 → 加空格
def munge(input: AnyStr, limit=1000): ...   # 无注解 → 不加

# 错误
def complex(real, imag = 0.0):
    return magic(r = real, i = imag)

另外 PEP 8 还有一条「Pet Peeves」：不要为了对齐而使用多于一个空格。

5 · 应用场景

场景 1：用 // % / 做一份数据小结

假设你统计了一批文章的阅读量，要输出「平均阅读量」和「平均每篇多少字」：

total_views = 128430
article_count = 37

avg_views = total_views / article_count        # 3471.08...  / 得到精确的浮点结果
per_bucket = total_views // article_count      # 3471         // 得到整数，用于「每篇至少多少」
rest = total_views % article_count             # 剩下来的零头

print(f"平均 {avg_views:.1f} 次阅读，约 {per_bucket} 次的整份，余 {rest} 次")
# 平均 3471.1 次阅读，约 3471 次的整份，余 33 次

知识点对应：官方教程明确「/ 总是返回浮点数」，// 为整除，% 为余数，且 x == (x // y) * y + (x % y)。

场景 2：用 or 给缺失字段兜底 + 用比较运算符做筛选

从表格里读出来的数据常常缺字段，or 的「返回操作数本身」这一特性正好用得上：

raw_title = ""
raw_source = "科技日报"

title = raw_title or "（无标题）"      # '' 为假 → 返回右边 → "（无标题）"
source = raw_source or "未知来源"      # 非空为真 → 返回左边 → "科技日报"

views = 12800
if views >= 10000 and source != "未知来源":
    print(f"{title} | {source} | 热文")

这里的 and 也是短路的：如果 views >= 10000 为假， 右边根本不会被求值 —— 官方的说法是「它只在第一个参数为真时才求值第二个参数」。

再补一个身份比较的标准用法：从表格里取出来的空值常常是 NaN 或 None， 判断时用 is None，不要用 == None（官方 FAQ 的建议是「其他大多数情况下，都不建议使用身份相等性测试」， 但判断 None 恰恰是它被推荐的标准场景）。

6 · 概念辨析

辨析 1：= 与 ==（最高频的笔误）

views = 100        # 赋值：把 100 贴到名字 views 上
views == 100       # 比较：问「views 是不是等于 100」→ True / False

在 if 里写成 if views = 100 会直接 SyntaxError（Python 不像 C 那样允许赋值表达式混进条件里）。 这算是好事：错误当场暴露，而不是悄悄跑出错误结果。

辨析 2：/ 与 // —— 不是「精度」的区别，是「结果类型」的区别

表达式///
17 / 3 类17/3 = 5.66666666666666717//3 = 5
返回类型总是 float整数操作数给 int，浮点操作数给 float
取整方向不取整朝负无穷（-7//2 = -4）

不要以为 // 是「丢掉小数部分」——那是 int() 的行为。这两者对负数结果不同：int(-3.5) 是 -3，-3.5 // 1 是 -4.0。

辨析 3：== 与 is

两者回答的是不同问题：「内容一样吗」 vs 「是同一个东西吗」。 官方 FAQ 的原话是「is 运算符可用于测试对象的身份相等性。a is b 等价于 id(a) == id(b)」， 并明确不建议用它测常量值。反过来，is 的两个正当用途是：判断 None，以及判断单例对象。

辨析 4：and / or 与 & / |

它们长得像，但属于两类运算符：前者是逻辑运算（短路、返回操作数本身），后者是位运算（不短路、对整数按位算）。 对布尔值使用 & / | 语法上可行，但官方明确「应优先使用 and、or 和 !=」。 最实际的差别是短路：x != 0 and 1/x > 1 不会崩，x != 0 & 1/x > 1 会。

辨析 5：+= 与 s = s + ... 在列表上不完全等价

对数字完全等价；对可变序列，官方文档写明 s += t 的效果是「用 t 的内容扩展 s」（约等于 s[len(s):len(s)] = t）， 是就地修改。所以当另一个变量也指向同一个列表时，它会被一起改到。这一点在《列表》那份资料里会展开。

辨析 6：链式比较容易看错

x < y > z 是合法表达式，等价于 x < y and y > z， 它没有比较 x 和 z。官方原文专门提醒了这一点：a op1 b op2 c 不意味着在 a 和 c 之间做任何比较。 想比较 x 和 z 就明确写出来。

7 · 自测问题

Q1：17 / 3、17 // 3、17 % 3 分别是多少？三者什么关系？
依次是 5.666666666666667、5、2。关系是官方给出的恒等式：17 == (17 // 3) * 3 + (17 % 3)，即 5*3+2。
Q2：-7 // 2 和 -7 % 2 分别是多少？
-4 和 1。整除是朝负无穷取整（-3.5 → -4），不是截断；取模结果的符号跟随第二个操作数（这里是正数 2），所以是 1。验证：(-7 // 2) * 2 + (-7 % 2) == -8 + 1 == -7。
Q3：-3 ** 2 和 (-3) ** 2 结果一样吗？为什么？
不一样：-9 和 9。** 的优先级高于一元负号，所以 -3 ** 2 被解释为 -(3 ** 2)。这是官方教程脚注明确点出的坑。
Q4："" or "default"、[] and "x" 分别得到什么？
'default' 和 []。or 在左边为假时返回右边；and 在左边为假时短路并返回左边本身（空列表，不是 False）。这就是官方说的「返回最后被求值的操作数」。
Q5：a = [1, 2]、b = [1, 2]，a == b 和 a is b 分别是什么？判断 None 该用哪个？
True 和 False。两个列表内容一样（== 为真），但是两个不同对象（is 为假）。判断 None 用 is，即 x is None。
Q6："1" + 1 会怎样？1 + 1.0 呢？
"1" + 1 抛 TypeError（+ 对 str 与 int 的组合没有定义）；1 + 1.0 得到 2.0，因为混合数值类型会把「较窄」的 int 拓宽为 float。
Q7：lists = [[]] * 3 之后执行 lists[0].append(1)，lists 变成什么？正确写法是什么？
变成 [[1], [1], [1]]，因为三个元素是同一个列表对象的引用。正确写法是推导式 [[] for i in range(3)]。这是官方文档专门警告的例子。
Q8：为什么建议用 and 而不是 & 来连接条件？
因为 and 短路（第一个操作数为假时不再求值第二个），而 & 会两侧都算，可能引发除零之类的意外错误。官方也明确建议优先使用 and、or 和 !=。
