1. 个人理解（先说人话）

前面几节你处理文本，用的都是「精确匹配」：if 标题 == "某市启动改造"、 if "人工智能" in 正文。这些只能回答「有没有」这个问题。

但新闻数据里的问题往往是这样问的：

  • 这 3000 条评论里，所有手机号都要打码——手机号长什么样？「1 开头、11 位数字」。
  • 把这份稿件里所有日期统一成 2026-09-17 格式——日期长什么样？「四位年-两位月-两位日」，但原文里可能是「2026年9月17日」。
  • 找出所有提到「某某区某某街道」的段落——这个「某某」是不确定的字符串。

正则表达式就是一门用来描述「长什么样的字符串」的迷你语言。 你不是在给 Python 一串具体文字，而是在给它一个模式（pattern）， 让它自己去找所有符合这个模式的文本。

把它想象成图书馆检索："人工智能" in 正文 是「找一本书名完全叫《人工智能》的书」； 而正则表达式是「找所有书名形如《XX 与 XX》的书」——你在描述形状，不是在指定内容。

这门语言很小，核心符号不到 20 个，但威力很大。代价是：它写出来像乱码。 所以本节的重点有两块：一是让你能读懂 r"\d{4}-\d{2}-\d{2}" 这种串， 二是让你知道什么时候不该用它——新手最常见的错误是用正则去解 HTML 和 JSON， 那会痛不欲生，因为你已经有 BeautifulSoup 和 json 了。

2. 学习目标

学完这一份，你应该能做到：

  • 能说出正则表达式解决的是「模糊搜索」问题，而不是「精确匹配」问题。
  • 能读懂并能手写这些基本元字符：. * + ? {m,n} [] () | ^ $ 和 \d \w \s。
  • 能解释为什么正则表达式字符串前面必须加 r，并说出不加会发生什么。
  • 能区分 re.search() / re.match() / re.fullmatch() 的区别（这是新手第一大坑）。
  • 能区分贪婪和非贪婪量词，能解释为什么 <.*> 会吃掉整行，而 <.*?> 不会。
  • 能用 re.findall() 抽取、re.sub() 清洗、re.split() 切分，并知道用什么函数拿到分组。
  • 能写出匹配中文的正则表达式（[\u4e00-\u9fa5]），并知道它为什么不是唯一的写法。
  • 能用 re.compile() + re.VERBOSE 写出可读的长正则。
  • 知道正则的两个主要限制：不能解析嵌套结构（如 HTML、JSON），回溯可能很慢。

4. 结构化解释

4.1 定义

官方对 re 模块的第一句介绍：

本模块提供了与 Perl 语言类似的正则表达式匹配操作。

模式和被搜索的字符串既可以是 Unicode 字符串（str），也可以是 8 位字节串（bytes）。 两者不能混用：不能将 Unicode 字符串与字节串模式进行匹配，反之亦然； 执行替换时，替换字串的类型也必须与所用的模式和搜索字串的类型一致。 ——引自 Python 标准库 re 模块文档开头

所以：正则表达式不是数据类型，是一种字符串的写法约定。 你传给 re 的都是字符串，只不过 re 会给某些字符赋予特殊含义。

4.2 最小模型：正则是一门「描述形状」的语言

把正则表达式想象成通缉令上的画像。通缉令不会写具体名字，它会写： 「身高 175 上下、戴眼镜、左眉有疤」。警方拿着这份画像去人群中找所有符合的人。

通缉令措辞正则里对应什么例子
「随便什么」.a.c 匹配 abc、a2c、a c
「0 个或多个」*ab* 匹配 a、ab、abbb
「至少 1 个」+ab+ 匹配 ab、abbb，但不匹配 a
「有或没有都行」?ab? 匹配 a 或 ab
「正好 4 位」{4}\d{4} 匹配 2026，不匹配 202
「2 到 4 位」{2,4}\d{2,4} 匹配 26、2026
「这几个中的一个」[...][abc] 匹配 a 或 b 或 c
「这几个形状的一个」|cat|dog 匹配 cat 或 dog
「这一段要单独拿出来」(...)(\d{4})-(\d{2}) 能分别提取年月
「必须是开头」^^2026 只匹配以 2026 开头的
「必须是结尾」$。$ 只匹配以句号结尾的

这个「通缉令」模型解释了一个新手常困惑的现象： 为什么 re.search(r"A.I", "我买了个 A4I 纸") 能找到东西， 而 "A.I" in "我买了个 A4I 纸" 找不到？ 因为前者在按「形状」找（A + 任意一个字符 + I），后者在按「文字」找。

4.3 关键机制一：r"..." —— 为什么必须加这个 r

这是新手的第一道门槛，也是官方专门用一节来讲的东西。官方原文：

正则表达式使用反斜杠字符（'\'）表示特殊形式或是允许在使用特殊字符时不引发它们的特殊含义。 这会与 Python 在字符串字面值中对于相同字符出于相同目的规定的用法发生冲突； 例如，要匹配一个反斜杠字面值，用户将必须写成 '\\\\'， 因为正则表达式必须为 \\，而每个反斜杠在普通 Python 字符串字面值中又必须表示为 \\。 ——引自 Python 标准库 re 模块文档「原始字符串标记」节前

官方给出的解决方案：

解决办法是对于正则表达式模式（patterns）使用 Python 的原始字符串表示法； 在带有 'r' 前缀的字符串字面值中，反斜杠不必做任何特殊处理。 因此 r"\n" 表示包含 '\' 和 'n' 两个字符的字符串， 而 "\n" 则表示只包含一个换行符的字符串。 模式在 Python 代码中通常都使用原始字符串表示法。 ——引自 Python 标准库 re 模块文档「原始字符串标记」节

官方还给了两组「完全一致」的对照代码：

>>> re.match(r"\W(.)\1\W", " ff ")
<re.Match object; span=(0, 4), match=' ff '>
>>> re.match("\\W(.)\\1\\W", " ff ")
<re.Match object; span=(0, 4), match=' ff '>
>>> re.match(r"\\", r"\\")
<re.Match object; span=(0, 1), match='\\'>
>>> re.match("\\\\", r"\\")
<re.Match object; span=(0, 1), match='\\'>

看到第二组了吗？想匹配一个反斜杠：

  • 用 r"\\"：两个字符，一眼能数清。
  • 用 "\\\\"：四个反斜杠。因为 Python 字符串层要先吃掉两个，剩下两个给正则。

所以规则很简单：凡是正则表达式，一律加 r。没有例外。

官方还提到一个未来的变化，值得提前知道：

注意：Python 的字符串字面值中使用的反斜杠，若有任何无效转义序列将产生 SyntaxWarning， 并将在未来改为 SyntaxError。此行为即使对于正则表达式来说有效的转义字符同样会发生。 ——引自 Python 标准库 re 模块文档开头

意思是："\d" 这种写法现在会警告，以后会直接报错。 这也是「一律加 r」的另一个理由。

4.4 关键机制二：search / match / fullmatch —— 三个函数的区别

官方对三者的定义：

函数官方说明记忆口诀
re.match(pattern, string) 如果 string 开头的零个或多个字符与正则表达式 pattern 匹配，则返回相应的 Match。
注意即便是 MULTILINE 多行模式，re.match() 也只匹配字符串的开始位置，而不匹配每行开始。		 只看开头
re.search(pattern, string) 扫描整个 string 查找正则表达式 pattern 产生匹配的第一个位置，并返回相应的 Match。 到处找，找第一个
re.fullmatch(pattern, string) 如果整个 string 与正则表达式 pattern 匹配，则返回相应的 Match。 整串必须完全匹配

官方示例（deque 之外最值得背下来的一个）：

>>> re.match("c", "abcdef")    # 不匹配
>>> re.search("c", "abcdef")   # 匹配
<re.Match object; span=(2, 3), match='c'>
>>> re.fullmatch("p.*n", "python") # 匹配
<re.Match object; span=(0, 6), match='python'>
>>> re.fullmatch("r.*n", "python") # 不匹配

官方还有一段关于「用 ^ 来限制 search」的说明：

>>> re.match("c", "abcdef")    # 不匹配
>>> re.search("^c", "abcdef")  # 不匹配
>>> re.search("^a", "abcdef")  # 匹配
<re.Match object; span=(0, 1), match='a'>

以及 MULTILINE 的影响：

>>> re.match("X", "A\nB\nX", re.MULTILINE)  # 不匹配
>>> re.search("^X", "A\nB\nX", re.MULTILINE)  # 匹配
<re.Match object; span=(4, 5), match='X'>
新手的经典错误：想判断「这一行是不是手机号」，写 re.match(r"\d{11}", 行)。 结果是——只要一行以 11 位数字开头就通过，哪怕后面跟着「abc」。 判据：要判断「整串是什么」，用 fullmatch； 要「在文本里找符合的东西」，用 search；match 只在少数「以 X 开头」的场景用。

4.5 关键机制三：Match 对象与分组

官方对 Match 对象的介绍：

匹配对象总是有一个布尔值 True。如果没有匹配的话 match() 和 search() 返回 None， 所以你可以简单的用 if 语句来判断是否匹配 ——引自 Python 标准库 re 模块「匹配对象」节

所以标准写法是：

m = re.search(pattern, text)
if m:                 # 千万别写 if m == True，也不要用 try
    process(m)

关于 group()，官方说明：

返回一个或者多个匹配的子组。如果只有一个参数，结果就是一个字符串；如果有多个参数，结果就是一个元组且其中每项都对应一个参数。 如果没有参数，则 group1 默认为零（即返回整个匹配）。 如果 groupN 参数为零，则对应的返回值就是整个匹配字符串；如果是一个正整数，则为匹配对应带圆括号分组的字符串。

如果一个分组包含在模式的某一未匹配的部分之中，则对应的结果为 None。 如果一个分组包含在模式的某一多次匹配的部分之中，则返回最后一个匹配。 ——引自 Python 标准库 re 模块「匹配对象」节 
>>> m = re.match(r"(\w+) (\w+)", "Isaac Newton, physicist")
>>> m.group(0)       # 整个匹配
'Isaac Newton'
>>> m.group(1)       # 第一个圆括号标记的子分组。
'Isaac'
>>> m.group(2)       # 第二个圆括号标记的子分组。
'Newton'
>>> m.group(1, 2)    # 使用多个参数则返回一个元组。
('Isaac', 'Newton')

「多次匹配只返回最后一个」的例子：

>>> m = re.match(r"(..)+", "a1b2c3")  # 匹配 3 次。
>>> m.group(1)                        # 只返回最后一个匹配。
'c3'

常用方法速查：

方法作用示例
m.group(0) 或 m[0]整个匹配到的字符串'Isaac Newton'
m.group(1) / m[1]第 1 个分组'Isaac'
m.groups()所有分组组成的元组('24', '1632')
m.groupdict()命名分组组成的字典{'first_name': 'Malcolm', ...}
m.start() / m.end()匹配的开始 / 结束位置见官方 email 示例
m.span()(start, end) 元组(0, 6)

官方的 groups() 与 groupdict() 示例：

>>> m = re.match(r"(\d+)\.(\d+)", "24.1632")
>>> m.groups()
('24', '1632')

>>> m = re.match(r"(\d+)\.?(\d+)?", "24")
>>> m.groups()      # 第二个分组默认为 None。
('24', None)
>>> m.groups('0')   # 现在，第二个分组默认为 '0'。
('24', '0')

>>> m = re.match(r"(?P<first_name>\w+) (?P<last_name>\w+)", "Malcolm Reynolds")
>>> m.groupdict()
{'first_name': 'Malcolm', 'last_name': 'Reynolds'}

官方那个很巧妙的 start()/end() 用法（可以用来「删掉文本中间某一段」）：

>>> email = "tony@tiremove_thisger.net"
>>> m = re.search("remove_this", email)
>>> email[:m.start()] + email[m.end():]
'tony@tiger.net'

4.6 关键机制四：贪婪 vs 非贪婪

这是正则里最容易写出 bug 的地方。官方原文：

'*', '+' 和 '?' 数量限定符都是贪婪的；它们会匹配尽可能多的文本。 有时这种行为并不被需要；如果 RE <.*> 针对 '<a> b <c>' 进行匹配， 它将匹配整个字符串，而不只是 '<a>'。

在数量限定符之后添加 ? 将使其以非贪婪或最小风格来执行匹配； 也就是将匹配数量尽可能少的字符。使用 RE <.*?> 将只匹配 '<a>'。 ——引自 Python 标准库 re 模块「重复」节

官方的另一个例子（数字范围）：

例如，在 6 个字符的字符串 'aaaaaa' 上，a{3,5} 将匹配 5 个 'a' 字符， 而 a{3,5}? 将只匹配 3 个字符。 ——引自 Python 标准库 re 模块 {m,n}? 条目

完整对照表：

类型语法行为
贪婪（默认）* + ? {m,n}官方：「都是贪婪的；它们会匹配尽可能多的文本」
非贪婪（最小）*? +? ?? {m,n}?官方：「将使其以非贪婪或最小风格来执行匹配；也就是将匹配数量尽可能少的字符」
占有型（3.11+）*+ ++ ?+ {m,n}+官方：「在之后的表达式匹配失败时不允许反向追溯」，性能优化用，初学可以不管
 
import re

text = "<a> 新闻标题 </a> <a> 另一个标题 </a>"

# ❌ 贪婪：.* 吃到最后一个 >，整个串都被吃进第一个匹配
re.findall(r"<a>.*</a>", text)
# ['<a> 新闻标题 </a> <a> 另一个标题 </a>']   ← 只找到 1 个，而且是整串

# ✅ 非贪婪：.*? 吃到最近的 </a> 就停
re.findall(r"<a>.*?</a>", text)
# ['<a> 新闻标题 </a>', '<a> 另一个标题 </a>']   ← 找到 2 个，正确
实用口诀：提取「一对标记之间的内容」时，一律用非贪婪 .*?。 只有当 .*? 结果不对时，才回去考虑贪婪。

4.7 关键机制五：字符集合与特殊序列

官方对 [] 字符集合的说明（要点摘录）：

  • 字符可以单独列出，比如 [amk] 匹配 'a'，'m'，或者 'k'。
  • 可以表示字符范围，通过用 '-' 将两个字符连起来。比如 [a-z] 将匹配任何小写 ASCII 字符，[0-5][0-9] 将匹配从 00 到 59 的两位数字。
    如果 - 进行了转义（比如 [a\-z]）或者它的位置在首位或者末尾（如 [-a] 或 [a-]），它就只表示普通字符 '-'。
  • 除反斜杠外的特殊字符在集合中会失去其特殊含义。例如，[(+*)] 将匹配字符字面值 '(', '+', '*', 或 ')' 中的任何一个。
  • 不在集合范围内的字符可以通过取反来进行匹配。如果集合首字符是 '^'，所有不在集合内的字符将会被匹配，比如 [^5] 将匹配所有字符，除了 '5'。
  • 要在集合内匹配一个 ']' 字面值，可以在它前面加上反斜杠，或是将它放到集合的开头。
——引自 Python 标准库 re 模块「字符集合」节

第三点非常重要，解释了一个高频困惑：[.] 只匹配「一个真实的点」，不是「任意字符」。 因为 . 在集合里失去了特殊含义。 所以「匹配文件名里的点」应该写 r"\."（转义）或 r"[.]"（放进集合）。

常用特殊序列（官方定义节选）：

序列官方说明
\d Unicode（str）样式：匹配任意 Unicode 十进制数码（即任何属于 Unicode 字符类别 [Nd] 的字符）。这包括 [0-9]，还包括许多其他的数码类字符。如果使用了 ASCII 旗标则匹配 [0-9]。
\w Unicode（str）样式：匹配 Unicode 单词类字符；这包括所有 Unicode 字母数字类字符（由 str.isalnum() 定义），以及下划线（_）。如果使用了 ASCII 旗标则匹配 [a-zA-Z0-9_]。
\s Unicode（str）样式：匹配 Unicode 空白字符（如 str.isspace() 所定义的）。这包括 [ \t\n\r\f\v]，还包括许多其他字符，例如许多语言中由排版规则约定的非中断空白字符。
\b 匹配空字符串，但只在单词开始或结尾的位置。一个单词被定义为一个单词字符的序列。注意在通常情况下，\b 被定义为 \w 和 \W 字符之间的边界（反之亦然），或是 \w 和字符串开始或结尾之间的边界。
备注：在一个字符范围内，\b 代表退格符。
\. \* \+ 等 官方：转义特殊字符（允许你匹配 '*', '?', 或者此类其他），或者表示一个特殊序列。

注意 \w 和 \d 的官方定义是 Unicode 级别的，不只是 ASCII。 这意味着 \w 能匹配中文——这一点很多人不知道，也不知道它有时会带来麻烦 （比如你想只匹配英文单词时，\w+ 会把中文也吃进去）。 这种时候要加 re.ASCII 旗标，或者显式写 [a-zA-Z]。

关于 .（点号），官方定义：

在默认模式下，匹配除换行符以外的任意字符。如果指定了旗标 DOTALL，它将匹配包括换行符在内的任意字符。 ——引自 Python 标准库 re 模块「特殊字符」节

4.8 关键机制六：四个最常用的函数

函数返回用途
re.search(p, s)Match 或 None判断「有没有」，或取第一处
re.findall(p, s)列表（字符串或元组）抽取所有符合的片段
re.sub(p, repl, s)新字符串替换 / 清洗
re.split(p, s)列表按复杂规则切分

findall 的返回值取决于有几个分组，这一点官方说得很清楚：

返回结果取决于模式中捕获组的数量。如果没有组，返回与整个模式匹配的字符串列表。 如果有且仅有一个组，返回与该组匹配的字符串列表。 如果有多个组，返回与这些组匹配的字符串元组列表。非捕获组不影响结果。 ——引自 Python 标准库 re 模块 findall 条目 
>>> re.findall(r'\bf[a-z]*', 'which foot or hand fell fastest')
['foot', 'fell', 'fastest']
>>> re.findall(r'(\w+)=(\d+)', 'set width=20 and height=10')
[('width', '20'), ('height', '10')]

sub 的官方说明：

返回通过使用 repl 替换在 string 最左边非重叠出现的 pattern 而获得的字符串。如果样式没有找到，则不加改变地返回 string。 repl 可以是字符串或函数；如为字符串，则其中任何反斜杠转义序列都会被处理。

向后引用像是 \6 会用样式中第 6 组所匹配到的子字符串来替换。

可选参数 count 是要替换的模式的最大出现次数；count 必须是一个非负整数。如果省略或为零，则将全部替换。 ——引自 Python 标准库 re 模块 sub 条目 
>>> def dashrepl(matchobj):
...     if matchobj.group(0) == '-': return ' '
...     else: return '-'
...
>>> re.sub('-{1,2}', dashrepl, 'pro----gram-files')
'pro--gram files'
>>> re.sub(r'\sAND\s', ' & ', 'Baked Beans And Spam', flags=re.IGNORECASE)
'Baked Beans & Spam'

官方还提到一个容易踩的细节：

相邻的空匹配没有可能，但一个空匹配可以在一个非空匹配之后立即发生。 因此，sub('x*', '-', 'abxd') 将返回 '-a-b--d-' 而不是 '-a-b-d-'。 ——引自 Python 标准库 re 模块 sub 条目

这说明：当你的模式可以匹配空字符串（比如 x*、\d*）时， sub 会在每个位置都插一次替换文本，结果会多于预期。 写 sub 时尽量用 + 而不是 *。

split 的官方示例：

>>> re.split(r'\W+', 'Words, words, words.')
['Words', 'words', 'words', '']
>>> re.split(r'(\W+)', 'Words, words, words.')
['Words', ', ', 'words', ', ', 'words', '.', '']
>>> re.split(r'\W+', 'Words, words, words.', maxsplit=1)
['Words', 'words, words.']
>>> re.split('[a-f]+', '0a3B9', flags=re.IGNORECASE)
['0', '3', '9']

注意第二行：如果分隔符里有捕获括号，分隔符本身也会留在结果里。这常被用来「保留分隔符」。

4.9 关键机制七：compile、旗标与 VERBOSE

官方对 re.compile() 的说明：

将正则表达式模式编译为一个正则表达式对象，可以被用于通过这个对象的方法 match(), search() 以及如下所述的其他方法进行匹配。

如果需要多次使用这个正则表达式的话，使用 re.compile() 和保存这个正则对象以便复用，可以让程序更加高效。

备注：通过 re.compile() 编译后的样式，和模块级的函数会被缓存，所以少数的正则表达式使用无需考虑编译的问题。 ——引自 Python 标准库 re 模块 compile 条目

常用旗标：

旗标官方说明内联写法
re.IGNORECASE / re.I 执行忽略大小写的匹配；[A-Z] 这样的表达式也将匹配小写字母。完全的 Unicode 匹配（如 Ü 将匹配 ü）同样适用。 (?i)
re.MULTILINE / re.M 在指定之后，模式字符 '^' 将匹配字符串的开始和每一行的开头（紧随在换行符之后）；而模式字符 '$' 将匹配字符串的末尾和每一行的末尾（紧接在换行符之前）。 (?m)
re.DOTALL / re.S 使 '.' 特殊字符匹配任意字符，包括换行符；如果没有这个旗标，'.' 将匹配除去换行符以外的任意字符。 (?s)
re.VERBOSE / re.X 允许你通过在视觉上分隔表达式的逻辑段落和添加注释来编写更为友好并更具可读性的正则表达式。表达式中的空白符会被忽略，除非是在字符类中，或前面有一个未转义的反斜杠……当一个行内包含不在字符类中并且前面没有未转义反斜杠的 # 时，则从最左边的此 # 直至行尾的所有字符都会被忽略。 (?x)
re.ASCII / re.A 使 \w, \W, \b, \B, \d, \D, \s 和 \S 执行仅限 ASCII 匹配而不是完整的 Unicode 匹配。 (?a)

官方给的 VERBOSE 示例——这是让长正则变得可读的关键技巧：

a = re.compile(r"""\d +  # 整数部分
                   \.    # 小数点
                   \d *  # 几个小数位""", re.X)
b = re.compile(r"\d+\.\d*")
# a 和 b 等价，但 a 看得懂

旗标可以组合：

pattern = re.compile(r"^来源：(.+)$", re.MULTILINE | re.IGNORECASE)

还有个很实用但常被忽略的函数 re.escape()：

转义 pattern 中的特殊字符。如果你想对任意可能包含正则表达式元字符的文本字符串进行匹配，它就是有用的。 ——引自 Python 标准库 re 模块 escape 条目 
>>> print(re.escape('https://www.python.org'))
https://www\.python\.org

4.10 关键机制八：中文匹配

Python 官方文档没有专门给出「怎么匹配中文」的条目（因为中文只是 Unicode 的一个区块）。 实践中最常用的写法是： 

import re

# 匹配汉字：[\u4e00-\u9fa5] 是最常见的写法
re.findall(r"[\u4e00-\u9fa5]+", "Hello 世界，Python 编程")
# ['世界', '编程']

# 更严谨的写法：用 Unicode 属性（需要第三方 regex 模块，或用 unicodedata 过滤）
# 标准库 re 不支持 \p{Han}，这一点和 Perl / Java 不同

关于 [\u4e00-\u9fa5] 要诚实说清三件事：

  1. \uXXXX 是 Unicode 转义，官方在「被接受的转义序列」中列出了 \u；它只在 Unicode（str）模式中被识别。
  2. \u4e00–\u9fa5 是「基本汉字区」（CJK Unified Ideographs）的主体范围。它不包含扩展区的生僻字、也不包含扩展 A 区等。对新闻文本来说够用，但严格说不完整。
  3. 如果只是想「匹配非 ASCII 的文字」，更简单的写法是 [^\x00-\x7f]+；如果要覆盖所有汉字，[\u4e00-\u9fff] 比 [\u4e00-\u9fa5] 稍宽一些。
还有一种绕开字符范围的方式：用 \w 加 Unicode 默认行为——因为官方说 \w 在 Unicode 模式下 「包括所有 Unicode 字母数字类字符（由 str.isalnum()` 定义）」，其中就包含汉字。 所以 \w+ 能匹配中文。但这会同时匹配英文和数字， 所以「只要中文」还是得用字符范围。

4.11 关键机制九：什么时候不该用正则

这一节没有官方条文，是实践共识，但非常重要：

任务❌ 别用正则✅ 该用什么
解析 HTML 页面re.findall(r"<a href=...", html)BeautifulSoup / lxml
读写 JSONre.findall(r'"标题": "(.+?)"', s)json.loads()
读写 CSVre.split(r",", line)csv 模块（能正确处理引号内的逗号）
判断「是不是数字」re.fullmatch(r"\d+", s)s.isdigit() 或 try: int(s)
判断「是不是手机号」（业务规则）复杂的正则先用简单正则筛长度，再用明确逻辑判断号段

核心理由有两条：一是 HTML / JSON 是嵌套结构，而正则本质上是「有限状态」的工具， 官方文档自己也引用了 Friedl 的书来说明它的边界；二是这些格式已经有成熟解析器，用正则等于重新发明轮子还更容易出错。

4.12 可运行代码：完整对错对比

坑 1：忘了 r 前缀

import re

# ❌ 不加 r：Python 先把 \d 当成「无效转义」，或者 \n 直接变成换行符
re.findall("\d+", "abc123")     # 会告 SyntaxWarning / DeprecationWarning
re.findall("\bword\b", "a word b")   # \b 变成了退格符！完全匹配不到

# ✅ 一律加 r
re.findall(r"\d+", "abc123")          # ['123']
re.findall(r"\bword\b", "a word b")   # ['word']

坑 2：match 和 search 搞混

# ❌ 用 match 找「文本里有没有日期」：只在开头找，中间有也找不到
re.match(r"\d{4}-\d{2}-\d{2}", "发布时间：2026-09-17")   # None！

# ✅ 用 search
re.search(r"\d{4}-\d{2}-\d{2}", "发布时间：2026-09-17")  # Match

# ❌ 判断「整串是不是日期」用 match：后面有垃圾也算过
bool(re.match(r"\d{4}-\d{2}-\d{2}", "2026-09-17 备注：xxx"))   # True，误判！

# ✅ 用 fullmatch
bool(re.fullmatch(r"\d{4}-\d{2}-\d{2}", "2026-09-17 备注：xxx"))  # False
bool(re.fullmatch(r"\d{4}-\d{2}-\d{2}", "2026-09-17"))            # True

坑 3：贪婪导致「一锅端」

html = "<h2>标题一</h2><p>正文</p><h2>标题二</h2><p>正文二</p>"

# ❌ 贪婪：.* 从第一个 <h2> 一直吃到最后一个 </h2>
re.findall(r"<h2>.*</h2>", html)
# ['<h2>标题一</h2><p>正文</p><h2>标题二</h2>']  ← 1 个，错的

# ✅ 非贪婪：.*? 吃到最近的 </h2> 就停
re.findall(r"<h2>.*?</h2>", html)
# ['<h2>标题一</h2>', '<h2>标题二</h2>']  ← 2 个，对的

# ✅ 更稳：用分组只取中间的内容
re.findall(r"<h2>(.*?)</h2>", html)
# ['标题一', '标题二']  ← 直接拿到干净内容

坑 4：. 匹配不到换行

text = "第一行\n第二行"

# ❌ 默认 . 不含换行符
re.search(r"第一行.+第二行", text)      # None

# ✅ 方案 A：加 DOTALL 旗标
re.search(r"第一行.+第二行", text, re.DOTALL)   # Match

# ✅ 方案 B：显式用 [\s\S]（这也是一个经典技巧）
re.search(r"第一行[\s\S]+第二行", text)         # Match

坑 5：^ $ 在默认模式下只管整串

text = "来源：A\n来源：B\n来源：C"

# ❌ 默认模式：^ 只匹配整个字符串的开头，只找到第 1 个
re.findall(r"^来源：(.+)$", text)
# ['A']                  ← 注意 $ 后面还有个 B？不，这里只匹配到第一个 \n 之前

# ✅ 加 MULTILINE：^ 和 $ 按「行」工作
re.findall(r"^来源：(.+)$", text, re.MULTILINE)
# ['A', 'B', 'C']

坑 6：findall 返回的东西不是你想要的

s = "宽=20 高=10"

# ❌ 有多个分组时，返回的是元组列表，不是字符串
re.findall(r"(\w+)=(\d+)", s)
# [('宽', '20'), ('高', '10')]        ← 想要的是 ['20', '10']？

# ✅ 用非捕获组 (?:...) 让非目标分组不参与返回
re.findall(r"(?:\w+)=(\d+)", s)
# ['20', '10']                        ← 正确

# ✅ 或者直接用 finditer 拿 Match 对象，自己取 group
for m in re.finditer(r"(\w+)=(\d+)", s):
    print(m.group(1), "→", m.group(2))
# 宽 → 20
# 高 → 10

坑 7：sub 里用 \1 要注意转义

s = "张三，男，1990年生"

# ❌ 替换串用普通字符串，\1 在 Python 字符串层就有歧义
# re.sub(r"(\d{4})年", "\1年生日", s)     # 可能出问题

# ✅ 替换串也用 raw 字符串
re.sub(r"(\d{4})年", r"生于 \1 年", s)
# '张三，男，生于 1990 年生'

# ✅ 命名组更清楚
re.sub(r"(?P<y>\d{4})年", r"生于 \g<y> 年", s)

坑 8：用正则代替本该有的字符串方法

s = "  某市  启动  改造  "

# ❌ 用正则做字符串方法就能做的事，又慢又难读
re.sub(r"^\s+|\s+$", "", s)
re.sub(r"\s+", " ", s)

# ✅ 用字符串自己的方法
s.strip()
" ".join(s.split())

# ❌ 判断前缀
re.match(r"来源", s)
# ✅
s.startswith("来源")

坑 9：用户输入直接拼进正则

user_input = "1+1=2"      # 也可能是 "C++"、"a.b" 等

# ❌ 直接拼接：+ 变成量词，. 变成通配符，结果完全不对甚至报错
# re.search(user_input, text)

# ✅ 用 re.escape 转义
re.search(re.escape(user_input), "计算结果 1+1=2 是对的")   # Match

坑 10：正则语法错误不处理

import re

# 正则表达式写错（比如括号不配对）会抛 re.PatternError（3.13 前叫 re.error）
try:
    re.compile(r"(\d+")
except re.PatternError as e:
    print("正则写错了：", e)
    print("出错位置：", e.pos)

# 官方对该异常的说明：
# 「当传递给某个函数的字符串不是合法的正则表达式（例如，它可能包含不匹配的圆括号）
#   或者当在编译或匹配期间出现其他错误时所引发的异常。
#   如果字符串未包含对某个模式的匹配绝不会导致错误。」
最后一句很重要：「没匹配到」永远不会报错，只会返回 None 或空列表。 报 PatternError 永远意味着「你的正则本身写错了」。

5. 应用场景（新闻传播学）

场景一：评论区数据脱敏 + 联系方式提取

真实场景：你要把一批读者留言做成公开数据集，但里面有手机号、身份证号、邮箱、QQ 号。 合规要求是必须脱敏才能发布。同时你还想把「愿意接受采访的读者」筛出来—— 这些人留了联系方式。这是一件事的两个方向：一个要抹掉，一个要提取。 

import re

# ---------- 1. 脱敏：把敏感信息替换成占位符 ----------
# 手机号：1 开头，第二位 3-9，共 11 位；用 \b 保证不是更长数字的一部分
phone_re = re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)")

# 身份证：18 位，最后一位可能是 X（用 17 位数字 + 校验位）
id_re = re.compile(r"(?<!\d)\d{17}[\dXx](?!\d)")

# 邮箱
email_re = re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+")

# 固定电话（带区号）
landline_re = re.compile(r"(?<!\d)0\d{2,3}-\d{7,8}(?!\d)")

def mask_sensitive(text):
    text = phone_re.sub("[手机号]", text)
    text = id_re.sub("[身份证]", text)
    text = email_re.sub("[邮箱]", text)
    text = landline_re.sub("[固话]", text)
    return text

message = "我住城东，电话13812345678，也可以发邮件到 reader@example.com，身份证 11010119900307123X"
print(mask_sensitive(message))
# 我住城东，电话[手机号]，也可以发邮件到[邮箱]，身份证 [身份证]


# ---------- 2. 提取：找出所有联系方式，做访谈名单 ----------
def extract_contacts(text):
    result = {}
    if m := phone_re.search(text):
        result["手机号"] = m.group(0)
    if m := email_re.search(text):
        result["邮箱"] = m.group(0)
    if m := landline_re.search(text):
        result["固话"] = m.group(0)
    return result

print(extract_contacts(message))
# {'手机号': '13812345678', '邮箱': 'reader@example.com', '固话': ...}

这段代码里几个值得注意的地方：

  • 用 (?<!\d) 和 (?!\d) 做边界：匹配「前后都不是数字」的位置。这样才不会被「1234567890123」（13 位）的中间部分误伤。这是官方文档里的两种断言，(?!...) 叫否定型前视断言，(?<!...) 叫否定型后视断言。
  • 用 re.compile() 预编译：因为这几个正则会反复用，官方说这样「可以让程序更加高效」。
  • 用海象运算符 := 简化「匹配并取值」：if m := phone_re.search(text) 一行完成两件事。
  • sub 全部替换 vs count=1：脱敏要全部替换（默认 count=0 就是全部）；如果只想替换第一处，传 count=1。

诚实提醒：手机号号段规则会变，身份证校验位有算法。生产环境里更稳的做法是 「简单的正则做初筛 + 明确的业务逻辑做判断」，不要把所有规则都塞进正则。

场景二：把杂乱的稿件日期统一成标准格式

真实场景：你收了 8 家媒体的稿子，日期写法五花八门：2026年9月17日、 2026-9-17、2026/09/17、26.9.17 等。 要做时间序列分析，必须先统一。这是正则替换的经典用法。 

import re
from datetime import date

# 用命名的分组，把「年 月 日」分别捕获，允许分隔符是 年/月/日、-、/、.
date_pattern = re.compile(r"""
    (?P<年>\d{4})           # 4 位年
    \s*                      # 可能有空格
    (?:年|[-/.])             # 分隔符：年 / - / / / .
    \s*
    (?P<月>\d{1,2})          # 1-2 位月
    \s*
    (?:月|[-/.])
    \s*
    (?P<日>\d{1,2})          # 1-2 位日
    \s*
    日?                      # 末尾的「日」可选
""", re.VERBOSE)


def normalize_date(text):
    """把文本里所有日期改写成 YYYY-MM-DD 格式，并返回改写后的文本与找到的日期列表。"""
    found = []

    def repl(m):
        y, mo, d = int(m["年"]), int(m["月"]), int(m["日"])
        try:
            normalized = date(y, mo, d).isoformat()     # 顺手校验：9月31日会抛 ValueError
        except ValueError:
            found.append((m.group(0), "非法日期"))
            return m.group(0)                     # 原样保留，但记录下来
        found.append((m.group(0), normalized))
        return normalized

    new_text = date_pattern.sub(repl, text)
    return new_text, found


draft = """
【3月15日讯】2026年9月17日，某市启动了老旧小区改造。
相关方案早在 2026-3-1 就已公示，后来又在 2026/09/05 做过一次修订。
补充报道时间是 2026.9.18。
"""

new_draft, records = normalize_date(draft)
print(new_draft)
print("--- 替换记录 ---")
for old, new in records:
    print(f"{old!r:20} → {new}")

这段代码的技术要点：

  • 用 re.VERBOSE 写长正则：官方说它「允许你通过在视觉上分隔表达式的逻辑段落和添加注释来编写更为友好并更具可读性的正则表达式」。上面这个正则如果挤成一行，没人看得懂。
  • 用命名分组 (?P<名>...)：比 \1、\2 清楚得多，官方也说「分组所匹配到的子字符串可通过符号分组名称 name 来访问」。
  • re.sub 的替换参数可以是函数：官方说「如果 repl 是一个函数，则它会针对每次 pattern 的非重叠出现的情况被调用。该函数接受单个 Match 参数，并返回替换字符串」。用函数的好处是可以顺手做校验——date(2026, 9, 31) 会抛 ValueError，于是非法日期不会被悄悄改错。
  • 不要用正则做日期计算：格式改写用正则，日期的合法性校验和加减用 datetime。各司其职。

另外注意 (?:年|[-/.]) 用的是非捕获组—— 官方说它「匹配在括号内的任何正则表达式，但该分组所匹配的子字符串不能在执行匹配后被获取」。 这里我们不需要拿分隔符，所以用非捕获组更干净，也不会影响 groupdict() 的结果。

6. 概念辨析

辨析 1："AI" in text vs re.search(r"A.I", text)

text = "我买了一套 A4I 打印纸"

# 精确找文字
print("AI" in text)                        # False
print("A4I" in text)                       # True

# 按形状找
import re
print(bool(re.search(r"A.I", text)))       # True —— . 匹配了那个 4
print(bool(re.search(r"A\dI", text)))      # True —— \d 也匹配 4
print(bool(re.search(r"A[A-Z]I", text)))   # False —— 4 不是字母

判据：你确切知道要找的文字 → 用 in；只知道「形状」或要提取变化的部分 → 用正则。 in 更快也更好读，能用就用它。

辨析 2：. vs [.] vs \.

s = "a.c abc"

re.findall(r"a.c", s)     # ['a.c', 'abc']  ← . 是通配符，两个都匹配
re.findall(r"a[.]c", s)   # ['a.c']         ← [] 里 . 失去特殊含义
re.findall(r"a\.c", s)    # ['a.c']         ← 转义后也是字面点

官方对 [] 里特殊字符的说明是：「除反斜杠外的特殊字符在集合中会失去其特殊含义」。 所以 [.] 和 \. 都可以，看个人习惯。但 [.*+?()] 这种写法比一串 \.\*\+\?\(\) 好读。

辨析 3：贪婪 .* vs 非贪婪 .*?

s = "<p>甲</p><p>乙</p>"

re.findall(r"<p>.*</p>", s)     # ['<p>甲</p><p>乙</p>']   ← 贪婪，一锅端
re.findall(r"<p>.*?</p>", s)    # ['<p>甲</p>', '<p>乙</p>']  ← 非贪婪，逐个

官方原文：贪婪的「会匹配尽可能多的文本」，加 ? 后「将匹配数量尽可能少的字符」。 结论：提取成对标记之间的内容，默认用非贪婪。

辨析 4：re.match vs re.search vs re.fullmatch

s = "发布时间：2026-09-17"

re.match(r"\d{4}-\d{2}-\d{2}", s)       # None    ← 只看开头
re.search(r"\d{4}-\d{2}-\d{2}", s)      # Match   ← 到处找
re.fullmatch(r"\d{4}-\d{2}-\d{2}", s)   # None    ← 要求整串就是日期

re.fullmatch(r"\d{4}-\d{2}-\d{2}", "2026-09-17")   # Match

官方对 match 的补充说明特别值得注意：「注意即便是 MULTILINE 多行模式， re.match() 也只匹配字符串的开始位置，而不匹配每行开始」。 所以如果你在逐行处理文本，每行单独调 match 是可以的； 但如果对整段文本调 match 并期望它匹配每一行，那是误解。

辨析 5：^/$ 默认 vs 加 MULTILINE

text = "A\nB\nC"

re.findall(r"^\w$", text)                  # []            ← 默认：只能是整串「单个字符」，A\nB\nC 不是
re.findall(r"^\w$", text, re.MULTILINE)    # ['A', 'B', 'C']  ← 按行匹配

官方说明：MULTILINE 让 '^' 「匹配字符串的开始和每一行的开头（紧随在换行符之后）」， '$' 「匹配字符串的末尾和每一行的末尾（紧接在换行符之前）」。 逐行提取（比如提取所有以「来源：」开头的行）必须加 MULTILINE。

辨析 6：正则 vs 专用解析器

import json

# ❌ 用正则解 JSON：嵌套一深就崩，转义、空格、顺序全都要考虑
s = '{"标题": "某市改造", "来源": {"名称": "日报", "级别": "市级"}}'
re.findall(r'"名称":\s*"(.+?)"', s)     # 这个简单例子能work，但稍微复杂就完蛋

# ✅ 用 json
data = json.loads(s)
print(data["来源"]["名称"])             # 日报

# ❌ 用正则解 HTML
# ✅ 用 BeautifulSoup / lxml
from html.parser import HTMLParser   # 标准库自带的最简方案

判断标准：数据里有「嵌套结构」或「转义规则」时，一定要用专用解析器。 正则擅长的是「扁平的、形状固定的文本」，比如手机号、日期、编号。

7. 自测问题

Q1：为什么正则表达式字符串前面要加 r？不加会有什么具体后果？
因为正则和 Python 字符串都用反斜杠做转义，会冲突。 官方原文：「要匹配一个反斜杠字面值，用户将必须写成 '\\\\'，因为正则表达式必须为 \\， 而每个反斜杠在普通 Python 字符串字面值中又必须表示为 \\」。 加 r 之后「反斜杠不必做任何特殊处理」，r"\\" 就是两个字符。 具体后果举例："\bword\b" 里的 \b 会被 Python 当成退格符，导致完全匹配不到； "\d" 会产生 SyntaxWarning（官方说未来会变成 SyntaxError）。 结论：凡是正则，一律加 r。
Q2：re.match(r"\d{4}", "年份：2026") 返回什么？为什么？怎么改？
返回 None。因为 re.match() 只检查字符串开头是否匹配， 而这里字符串以「年」字开头，不是数字。 官方对 match 的定义是「如果 string 开头的零个或多个字符与正则表达式 pattern 匹配」。 改成 re.search(r"\d{4}", "年份：2026") 就能匹配到。
Q3：下面两个表达式在 "<a>x</a><a>y</a>" 上结果有何不同？为什么？ 
re.findall(r"<a>.*</a>", s)
re.findall(r"<a>.*?</a>", s)
第一个返回 1 个元素（整个字符串），第二个返回 2 个元素。 因为 * 是贪婪的，官方说它「会匹配尽可能多的文本」，所以 .* 会一直吃到最后一个 </a>。 加 ? 变成非贪婪，「将匹配数量尽可能少的字符」，所以吃到最近的 </a> 就停。
Q4：re.findall(r"(\w+)=(\d+)", s) 和 re.findall(r"(?:\w+)=(\d+)", s) 的返回值有什么不同？
前者返回元组列表，如 [('width', '20'), ('height', '10')]； 后者返回字符串列表，如 ['20', '10']。 官方说明：「如果有多个组，返回与这些组匹配的字符串元组列表」；「非捕获组不影响结果」。 (?:...) 是「正则括号的非捕获版本……但该分组所匹配的子字符串不能在执行匹配后被获取」。 只要不想要的值，就用 (?:...) 或 finditer。
Q5：想要匹配「一行以『来源：』开头的内容」，为什么下面代码返回空列表？ 
text = "标题：A\n来源：某日报\n来源：通讯社"
re.findall(r"^来源：(.+)$", text)
因为默认模式下 ^ 只匹配整个字符串的开头，$ 只匹配整个字符串的末尾。 这里字符串开头是「标题：A」，所以匹配失败。 加 re.MULTILINE 就会让 ^ 匹配每一行的开头、$ 匹配每一行的末尾， 返回 ['某日报', '通讯社']。
Q6：为什么 re.compile(r"(\d+") 会报错，而 re.search(r"(\d+", "abc") 不会？
这两个都会报错。官方对 PatternError 的说明是： 「当传递给某个函数的字符串不是合法的正则表达式（例如，它可能包含不匹配的圆括号）…… 如果字符串未包含对某个模式的匹配绝不会导致错误」。 也就是说：「没匹配到」永远不报错（返回 None）；报错永远意味着「正则本身写错了」。 (\d+ 缺少右括号，是语法错误，编译阶段就抛异常。
Q7：要判断「用户输入的这个字符串」在文本里出现过，为什么必须用 re.escape()？举个例子。
因为用户输入里可能含有正则元字符，不转义的话它们会按特殊含义解释。 比如用户输入 "1+1=2"，+ 会被解释成「前面的字符重复 1 次以上」； 输入 "a.b"，. 会变成通配符；输入 "C++" 甚至可能让正则语义完全走样。 官方对 re.escape 的说明是：「转义 pattern 中的特殊字符。 如果你想对任意可能包含正则表达式元字符的文本字符串进行匹配，它就是有用的」。 正确写法：re.search(re.escape(用户输入), 文本)。
