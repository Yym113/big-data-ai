01 · 个人理解

我对「Skill」的人话版定义：

Skill = 一个带 YAML一种简洁的键值配置格式：用 --- 包裹，写 name: xxx / description: yyy 这种键值对 元数据的目录，里面装着「给 AI Agent 用的指令 + 可选脚本 + 可选资源」。它被激活时，指令文本会被注入到 context模型本轮看进去的全部文本，详见 llm-context.html 里，等同于「一段模块化的说明书」。

如果只能记一句话：Skill 是「被复用的 prompt 段 + 配套文件」——它不是改模型权重，而是临时往上下文里塞一段说明书。

04 · 结构化解释

4.1 定义（Anthropic 官方）

Skills are folders that include instructions, scripts, and resources that Claude can load when needed.
—— Introducing Agent Skills, Anthropic, 2025-10-16（2025-12-18 加入组织管理与开放标准）

官方进一步给出的四个特征：Composable（可组合）/ Portable（可移植）/ Efficient（按需加载）/ Powerful（可含可执行代码）。

4.2 最小目录结构

my-skill/
├── SKILL.md          # 必需：YAML 元数据 + Markdown 指令
├── scripts/          # 可选：可执行脚本（Python/Bash/Node）
├── references/       # 可选：按需加载的参考文档
└── assets/           # 可选：模板 / 静态资源

4.3 SKILL.md 的 YAML frontmatter

frontmatterYAML 写在 Markdown 文件最顶部、用 --- 包裹的元数据块 包含 name / description 等字段：

字段必填约束作用
name是1–64 字符；仅小写字母/数字/连字符；首尾不能是连字符；不能有两个连续连字符；必须等于所在目录名Skill 的唯一标识，决定 /<name> 命令
description是1–1024 字符；包含「做什么 + 何时用」的关键句帮 Agent 决定何时自动激活
license否许可证名或文件名声明可分发条款
compatibility否≤500 字符运行所需环境（产品、Python 版本、网络）
metadata否任意 KV作者、版本等扩展信息
allowed-tools否空格分隔字符串预授权可调工具（实验）

来源：Agent Skills 开放规范

4.4 一个最小 SKILL.md 示例

---
name: pdf-summarizer
description: 读取 PDF 并生成要点摘要。当用户提到 PDF / 论文 / 报告的总结请求时使用。
---

## 何时调用
- 用户上传 PDF 并请求「帮我总结一下」
- 用户说「这份 PDF 的关键点是什么」

## 工作流
1. 调用 scripts/extract.py 把 PDF 拆成章节
2. 对每章节生成 ≤5 条 bullet
3. 输出 Markdown 摘要

4.5 Skill 「激活」时实际发生了什么

  1. 用户请求进来，Agent 扫描所有已注册 Skill 的 description
  2. 命中描述 → 把 SKILL.md 的 Markdown 正文注入到当前 context
  3. 正文里的指令在 LLM 看来，相当于一段临时增加的系统级提示
  4. scripts/执行时不进 context（只把 stdout 注入），只有结果消耗 token
  5. references/ 是按需加载（不预先读全文）

所以 Skill 的「Efficient」特质来自：指令只在需要时进 context，而不是预先全塞进去。

05 · 应用场景

场景 A：项目级代码规范 Skill

在公司代码库里放一个 .workbuddy/skills/api-conventions/SKILL.md，描述 REST 命名、错误返回格式、参数校验规则。任何新写 API 的任务，Agent 都会自动先加载它再动手。

场景 B：报告生成 Skill（含脚本）

Skill 里附带 scripts/fetch_data.py + templates/report.md。用户说「写本周销售报告」，Agent 自动跑脚本 + 套模板，输出固定格式产物。

共同点：Skill 的价值是「把跨任务会重复的工作流封装成一个名字，调用一次就行」。

06 · 概念辨析 / 边界

  1. Skill ≠ Prompt：Prompt 是每次要主动写、贴在对话里的输入；Skill 是被自动发现、按需注入到 context 的模块化指令。
  2. Skill ≠ Tool：Tool 是被调用的函数（如 search、read_file），调用时模型决定要不要用；Skill 是被加载的说明，决定模型怎么想怎么做。
  3. Skill ≠ MCP：MCP（Model Context Protocol）是一套「给 Agent 暴露外部工具和数据源」的标准协议；Skill 是一个目录，里面可以引用 MCP 提供的工具。
  4. Skill ≠ Fine-tuning：Fine-tuning 会改模型权重；Skill 不会。Skill 只在当前 context 里追加文字。
  5. Skill 不等于 Plugin：Plugin（早期 Anthropic 用过的说法）现在已被 Skill 取代；但业内其他家类似概念命名不同（OpenAI 的 GPTs、Cursor 的 Rules、Google 的 Gems 等），原理相近。
