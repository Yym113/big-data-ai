01 · 个人理解

我对 Agent（智能体）的「人话版」定义：

Agent = 能感知环境 + 能做决定 + 能动手做事 的系统。它的目标不是「回答一个问题」，而是「把一件事做到底」。

如果只能记一句话：Agent 是一套「感知 → 推理 → 行动 → 看反馈」的循环，不是一次性的 Q&A。把 LLM 放到这个循环的「推理」环节、给它工具（Tools）和记忆（Memory），就是当下最常见的 LLM Agent。

04 · 结构化解释

4.1 定义（学术）

An agent is anything that can be viewed as perceiving its environment through sensors and acting upon that environment through actuators.
—— Russell & Norvig, Artificial Intelligence: A Modern Approach，常用教材名 AIMA

这个定义有意写得极宽：连恒温器都可以算 Agent（有温度传感器 + 加热执行器）。所以「智能」不是定义的关键，「能感知并作用于环境」才是。

4.2 最小模型

任何 Agent 都能套进这个三件套：

感知（percept） ──▶ 决策（policy / agent function）──▶ 动作（action）──▶ (环境反馈)
                       ▲                                          │
                       └───────────  反复迭代到目标  ──────────────┘

4.3 Russell & Norvig 的五类 Agent（由简单到复杂）

类别关键能力典型例子
简单反射if 条件 then 动作恒温器
基于模型的反射维护一份「世界内部模型」Roomba 早期版本
基于目标在心中规划「到目标状态的路径」导航 App、ChatGPT 的多步规划
基于效用给状态打效用分、选最大化期望效用下棋 AI
学习型有「性能元件 + 学习元件 + 评判器 + 问题生成器」现代 RL Agent、自博弈 AlphaGo

4.4 LLM Agent（当下最常见的形态）

2022 年起 ReAct 范式成为主流（Yao 等人，arXiv:2210.03629）：

ReAct = 把 Reasoning（思考/CoT） 和 Acting（调用工具） 交替进行： Thought 1 → Action 1 → Observation 1 → Thought 2 → Action 2 → …

为什么交替比「先全想完再动手」好？因为中途观察可以纠错、补信息，而纯推理幻觉会累积。

4.5 现代 LLM Agent 的常见组件

  • LLM（大脑）：负责推理、拆解、规划
  • Tools（工具）：搜索、文件读写、API、代码执行…
  • Memory（记忆）：短程（当前 context）vs 长程（向量库、笔记文件）
  • Planning（规划）：把目标拆成可执行子步骤
  • Loop controller（循环控制）：决定什么时候停、什么时候换路径

05 · 应用场景

场景 A：写代码 Agent

你给一句「帮我把这仓库里所有 `console.log` 换成 `logger.info`」，Agent 会：读目录 → 找到匹配文件 → 逐个改 → 跑测试确认没坏。它真的改文件，不是只生成一段 patch。

场景 B：研究 / 信息检索 Agent

你问「2024 年欧盟 AI Act 的关键条款 + 各方反应」，Agent 会：先搜索 → 读 PDF → 对比立场 → 整理成报告。它调用了多个工具（搜索、读文件、汇总），不是一次性 LLM 自答。

两个例子的共同点：Agent 的价值来自「能接入外部世界并动手」，而 LLM 是它的推理内核。

06 · 概念辨析 / 边界

  1. Agent ≠ Chatbot：Chatbot 只会「说话」；Agent 会「动手」。两者技术栈可以重叠，但目标函数不同。
  2. Agent ≠ Workflow：Workflow 是人写死的固定步骤；Agent 在运行时自己决定下一步。Workflow 更稳定但更僵；Agent 更灵活但更不可预测。
  3. Agent ≠ Autonomous（完全自治）：多数「Agent 产品」其实是人 + Agent协作，关键节点人确认后才继续。
  4. Agent ≠ LLM：LLM 是组件；Agent 是包含 LLM + Tools + Memory + Loop 的系统。把 LLM 叫做 Agent 不严谨。
  5. 什么时候不该用 Agent：① 一次性 Q&A 能答的；② 任务对「可控性、可复现」要求极高（如金融生产交易）；③ 没有可靠工具能调用的纯开放任务。

07 · 自测问题

  1. Agent 和 Chatbot 的本质区别是什么？
    答：Chatbot 只会对话；Agent 能感知环境 + 决定 + 执行动作。
  2. 一个 LLM Agent 通常包含哪几个核心组件？
    答：LLM（大脑）+ Tools（工具）+ Memory（记忆）+ Planning（规划）+ Loop controller（循环控制）。
  3. ReAct 框架里「Reasoning」和「Acting」是怎么配合的？
    答：两者交替出现——Thought → Action → Observation → Thought → …——让推理可以根据工具返回的观测纠正自己。
  4. Russell & Norvig 五类 Agent 的提升轴是什么？
    答：从「只看现在」到「看历史 + 模型」到「有目标」到「能比较效用」再到「能自我学习」，越来越复杂。
  5. 一句话说出 ReAct 论文的核心结论。
    答：推理 trace 和行动交错做，比纯 CoT 推理在交互决策任务上更强、且更可解释。
