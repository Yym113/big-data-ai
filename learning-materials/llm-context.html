01 · 个人理解

我对「大模型的上下文」的人话版定义：

Context = 模型某一次「看」进来的所有 token模型处理文本的最小单位；中文一字约 1 token，英文一词约 1–2 token 序列。它包含 system应用方写的指令段，如人设、规则、风格；用户通常不能改 提示、对话历史、检索回来的文档、工具返回结果、以及当前用户输入。

如果只能记一句话：LLM 是 stateless 的，每一轮对话的「记忆」不是模型记住的，而是你自己把过去的内容再次塞回 context。所以限制 context 窗口长度 = 限制了模型的「工作记忆」。

04 · 结构化解释

4.1 定义

Context = 一次 LLM 调用中送入模型的全部 token 序列 = system 消息 + 历史消息 + 用户消息 + 工具结果（按 chat template 排好）。

4.2 token 的最小模型

模型不直接看「字」，看的是token id 序列。一段中文 / 英文 / 代码会被切成不同数量的 token。例（粗略值）：

  • 1 个 ASCII 字符 ≈ 0.25–0.5 token
  • 1 个汉字 ≈ 1 token 左右（现代分词器常把 Bigram 拆开）
  • 1 个英文单词 ≈ 1–2 token

4.3 三大组成（按角色分）

角色是谁写常见内容用户能否改
system应用方人设、规则、风格、可用工具清单通常不能
user用户真实问题、追加的指令能
assistant模型之前的回复看不到
tool运行时注入工具调用结果（搜索、读文件…）不能直接改

4.4 上下文窗口（Context Window）

不是「模型看见的字数」，而是模型一次性吃下去的 token 上限。常见量级：

  • GPT-3.5：4K → 16K
  • GPT-4 / Claude 2：~100K
  • Claude 3 / 后续 / Gemini 等：200K–1M+

窗口变大 ≠ 窗口变好用。Liu et al. 2023 的 Lost in the Middle经验现象：相关信息在 context 中段时模型表现明显差于两端 论文显示：把相关信息放在 context 的开头或结尾，模型表现明显优于放在中间。

4.5 「Lost in the Middle」—— 为什么信息摆放位置很重要

论文：Lost in the Middle: How Language Models Use Long Contexts，Liu et al., 2023, arXiv:2307.03172。
核心发现：在多文档 QA / KV-retrieval 任务里，相关信息出现在 context 中段时，性能会显著下降；即使专为长 context 设计的模型也不能幸免。

工程意义：

  • RAG 检索结果要重排序，让最相关的放在最前 / 最后
  • 长 prompt 里关键指令放 system 段或最末尾
  • 不要假设模型在中间也能均匀利用

4.6 context engineering（上下文工程）

现在工业界流行的提法（见 Anthropic 工程博客）：把 context 当成「可被工程化的对象」，手段包括：

  • 补全：检索、工具结果注入（= RAG 的本质）
  • 压缩：长对话做摘要、剪枝
  • 隔离：把长信息放到子 Agent 的 context 里
  • 排序：对抗 lost-in-the-middle

05 · 应用场景

场景 A：RAG 问答

用户问「公司去年发布的隐私政策第 3 条是什么？」系统先搜向量库，把 top-3 段落塞到 user 消息后面、再把问题给 LLM。Context 的下半截就被「外部知识」填满了。

场景 B：多轮对话 + 工具调用

Agent 调「查天气 API」时，结果以 tool 角色插回 context，让下一轮 LLM 能看到。这是 ReAct 范式的核心。

共同点：context 不只是「用户输入」，而是应用层主动构造的、把 LLM 当成 reasoning kernel 所需要的全部信息。

06 · 概念辨析 / 边界

  1. Context ≠ Prompt：Prompt 是你写好的输入模板；Context 是 LLM 实际看到的 token 序列（包括自动加的 chat template header、隐藏的 system prompt 等）。
  2. Context ≠ Memory：Context 是 per-call 的；Memory 是跨调用持久存在的（如向量库、本地笔记文件）。
  3. Context Window ≠ Max Output Tokens：前者是输入上限，后者是单次输出上限，两者独立。
  4. Context Window 大 ≠ 实际可用：Lost in the Middle 表明窗口再大，中间位置的信息也可能被「浪费」。
  5. Context 不解决「知识陈旧」：模型的「权重知识」是训练截止日的；让 LLM 知道新事实只能靠塞到 context 里（RAG / 工具）。
