概念关系说明：Agent · 大模型的上下文 · Skill

三份学习资料之间的关系图 + 关键论断 · 经本人核查

一句话的关系

Context 是 Agent 每次推理的「工作记忆」；Skill 是「按需注入到 context 里的模块化说明」。
Skill 改变 context 的内容，context 决定 Agent 能看见什么，Agent 用更丰富 / 更精准的 context 去做更好的决策。

三两两之间的关系

1. Skill ↔ Context（怎么影响）

  • Skill 激活的瞬间，会把 SKILL.md 的 Markdown 正文塞进当前 context（多数 chat template 加在 system 段或紧随 system 段）。
  • 没激活 = 不进 context。激活 = 占用 token、影响 LLM 当轮的所有推理。
  • 所以「Skill 的设计上限」=「context 还有空间」。这是为什么allowed-tools、disable-model-invocation 等字段存在的根因——它们都在帮忙控制 context 的占用。

2. Skill ↔ Agent（怎么被使用）

  • Agent 在循环里通过扫描 name + description 来决定要不要激活某个 Skill。
  • 对 Skill 作者来说，写好 description 就是在告诉 Agent：「我适合被用在这些场景下」。
  • 对使用者来说，写一个 Skill = 把「重复出现的多步操作」固化成 /<skill-name> 一次调用。
  • Skill 不属于「Agent 的核心循环」——它是 Agent 用来扩展能力的外部插件。

3. Context ↔ Agent（怎么被使用）

  • Agent = LLM-as-reasoning-kernel + 在 context 上操作的工具/记忆。
  • Agent 看到多少 = context 有多少；Agent 决定啥 = LLM 推理 + context 内容。
  • 所以设计 Agent 时，最关键的设计决策往往不是「选哪家的 LLM」，而是：我在 context 里塞什么、按什么顺序、要不要做摘要、检索时怎么排序。这整条链在 Anthropic 工程圈被叫做 context engineering。

三概念对照表

维度 Agent Context（LLM 上下文） Skill
本质 一套「感知 → 推理 → 行动」循环系统 一次 LLM 调用送入的全部 token 序列 带 YAML 元数据的目录 + 注入到 context 的指令
持久性 长期（一次会话 / 一次任务） per-call（每一次调用都重新构造） 长期（仓库里一份文件）
可被改吗 系统设计后基本固定 每轮都被重新构造 手动维护
对其他两个的影响 读取 context → 决定下一步 约束 Agent 的可见信息 激活时扩 / 改 context 的 system 段
「错的类比」 把 LLM 叫做 Agent ❌ 把 prompt 叫做 context ❌ 把 prompt 模板叫做 Skill ❌
反例 纯一次性 Q&A 不算 Agent 把训练数据当成 context ❌ 把 fine-tuning 叫做 Skill ❌

一个完整链路例子（跑一次会涉及三者）

用户请求：「帮我把昨天那份 PDF 里第三章的要点，整理成 Slack 消息格式」

  1. Agent 启动循环：用 LLM 理解意图，决定需要 PDF 读取 + 文本格式化两件事。
  2. Skill 命中 description，自动注入 context：
    • pdf-extractor：告诉 Agent 用哪个脚本读 PDF
    • slack-message-style：告诉 Agent Slack 格式规范（中文、≤200 字、不滥用 emoji）
  3. Context 实时变化：
    • system 段：除了原本人设，多了 pdf-extractor + slack-message-style 的指令
    • tools 段：声明可以调用的工具（读 PDF、发 Slack…）
    • user 段：用户原问题
  4. Agent 推理 + 行动：调读 PDF 工具 → 拿到第三章文本 → 再次输入 LLM，按 slack-message-style 格式化 → 调发 Slack 工具 → 结束。
  5. 结束：Skill 不消失（文件还在仓库），Context 重置，Agent 任务结束 / 进入下一轮。

三个常被混用词的「边界图」

  • Context ⊃ Tools 描述 ⊃ 已激活 Skills（Skill 激活后是 context 的一部分）。
  • Agent ⊃ LLM + Tools + Skills + Memory + Planner（Skill 是 Agent 可选的扩展，不是必须）。
  • Skill ⊥ Tool（垂直关系）：Skill 说的是「怎么做」，Tool 做的是「能调什么函数」。Skill 描述里可以引用 Tool。
