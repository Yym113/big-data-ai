1 · 个人理解（先说人话）

推导式就是「循环 + 判断 + 追加」这三件事的压缩写法。你写四行的事，它可以写成一行。 

# 老写法：四行
hot = []
for n in news:
    if n["浏览"] > 10000:
        hot.append(n["标题"])

# 推导式：一行
hot = [n["标题"] for n in news if n["浏览"] > 10000]

翻译规则很简单，从左往右读： 「我要 n["标题"]，对每一条 n 在 news 里，只要 n["浏览"] > 10000」。

看到一行看不懂的推导式，就把它倒着展开成循环：先写 for，再写 if，最后把最前面那个表达式塞进 append()。 反过来，看到「建空列表 → 循环 → 判断 → append」这个四步结构，就该想到能不能写成推导式。

然后说内置函数。Python 有一批「已经帮你写好的函数」，直接调用就行 —— len、sum、max、sorted、any、all…… 官方 FAQ 在讲「怎么让程序变快」时的第一条建议就是：「如果标准库已为某些操作提供了基础函数，则可能比所有自编的函数都要快」， 并明确点名「一定要用内置方法 list.sort() 或 sorted() 函数进行排序」。

一句话记住：推导式省的是行数，内置函数省的是你重写 bug 的机会。 能一行写清就用推导式；能调内置函数就别自己写循环。

2 · 学习目标

学完这份资料，你应该能：

  1. 把「循环 + 条件 + append」的代码改写成列表推导式，也能把推导式展开回循环；
  2. 区分列表推导式 [...]、集合推导式 {...}、字典推导式 {k: v ...} 和生成器表达式 (...)；
  3. 说出生成器表达式与列表推导式在内存上的差别，并知道什么时候该用哪一个；
  4. 用 sorted(可迭代对象, key=函数, reverse=True) 做自定义排序，并解释为什么它比多重 if 排序好；
  5. 用 sum / max / min / any / all 替代自己写的累加循环；
  6. 说出推导式「什么时候不该用」，并识别 lambda 在循环里的变量陷阱。

4 · 结构化解释

4.1 定义

推导式（comprehension）：一种用紧凑语法从一个可迭代对象构建新容器的方式。 官方教程：「列表推导式创建列表的方式更简洁。常见的用法为，对序列或可迭代对象中的每个元素应用某种操作， 用生成的结果创建新的列表；或用满足特定条件的元素创建子序列。」

官方的语法结构说明（原文）：「列表推导式的方括号内包含以下内容：一个表达式，后面为一个 for 子句， 然后，是零个或多个 for 或 if 子句。」

4.2 最小模型

squares = [x**2 for x in range(10)]
# [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]

# 等价的老写法（官方示例）
squares = []
for x in range(10):
    squares.append(x**2)

官方还给出了另一种等价写法，以及它推荐的结论：

squares = list(map(lambda x: x**2, range(10)))   # 也能实现
squares = [x**2 for x in range(10)]              # 官方：「上面这种写法更简洁、易读。」

4.3 类比

概念类比说明
列表推导式一条流水线：进料 → 筛 → 装盒一行说清「要什么、从哪来、什么条件」
生成器表达式同一个流水线，但不预先装盒要一个做一个，随手给你
字典推导式边筛边登记成台账产出的是一份「键→值」的表
集合推导式边筛边随手扔进不允许重复的筐自动去重
sorted(key=...)按你指定的「看哪个字段」排队给每个元素算一个排序依据
lambda现写现用的一次性小工具只写一个表达式，不给名字
any / all「有一个符合就行」/「全都得符合」找到第一个符合条件的就停止

4.4 推导式全家桶

# 列表推导式：[表达式 for 变量 in 可迭代对象 if 条件]
titles = ["AI 写稿上線", "算法推荐争议", "县级融媒体"]
lens = [len(t) for t in titles]                       # [6, 6, 5]
longs = [t for t in titles if len(t) >= 6]            # 过滤

# 官方示例
vec = [-4, -2, 0, 2, 4]
[x*2 for x in vec]            # [-8, -4, 0, 4, 8]
[x for x in vec if x >= 0]     # [0, 2, 4]
[abs(x) for x in vec]         # [4, 2, 0, 2, 4]

freshfruit = ['  banana', '  loganberry ', 'passion fruit  ']
[weapon.strip() for weapon in freshfruit]     # ['banana', 'loganberry', 'passion fruit']

[(x, x**2) for x in range(6)]                  # [(0,0), (1,1), (2,4), (3,9), (4,16), (5,25)]

# 展平嵌套列表（两个 for）
vec2 = [[1,2,3], [4,5,6], [7,8,9]]
[num for elem in vec2 for num in elem]         # [1,2,3,4,5,6,7,8,9]

# 集合推导式：自动去重
a = {x for x in 'abracadabra' if x not in 'abc'}    # {'r', 'd'}
sources = {a["来源"] for a in articles}              # 所有来源名（已去重）

# 字典推导式：产出一份「键→值」表
{x: x**2 for x in (2, 4, 6)}                   # {2: 4, 4: 16, 6: 36}
src_count = {s: 0 for s in sources}             # 初始化计数器
元组要加括号。官方专门举了这个错例：[x, x**2 for x in range(6)] 会报 SyntaxError: did you forget parentheses around the comprehension target?， 必须写成 [(x, x**2) for x in range(6)]。

4.5 生成器表达式：省内存的那一半

官方原文：「生成器表达式的语法与列表推导式相同，只是它们用圆括号而不是方括号括起来。」 并且指出：「在运行时，生成器表达式的求值结果是一个生成器迭代器，它产生的值与对应的列表推导式相同。」 

# 列表推导式：立刻把全部结果造出来放进内存
squares_list = [x**2 for x in range(10)]
squares_list          # [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]

# 生成器表达式：造一个「会算的机器」出来，不算
squares_gen = (x**2 for x in range(10))
squares_gen           # <generator object <genexpr> at ...>
list(squares_gen)     # [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]   算到这一步才产生值
# 内存差别：做同一个统计
import sys

data = list(range(1_000_000))

lst = [x * 2 for x in data]
gen = (x * 2 for x in data)

sys.getsizeof(lst)     # 约 8 MB（真的要装下 100 万个整数）
sys.getsizeof(gen)     # 约 200 字节（只记着怎么算）

# 求和时用生成器，不需要中间那一整个列表
total = sum(x * 2 for x in data)          # 推荐：省内存
total = sum([x * 2 for x in data])        # 能用，但白造了一个大列表

官方还给了括号可以省略的两种情况（原文示例）：

# 生成器表达式作为唯一位置参数时，可以省掉自己那对括号
sum(x ** 2 for x in range(10))            # 285

# 不是唯一参数时，必须自己带括号
sum((x ** 2 for x in range(10)), start=1000)   # 1285
生成器只能消费一次。 gen = (x for x in [1,2,3]) 之后 list(gen) 得到 [1,2,3]， 再 list(gen) 就只剩 [] 了 —— 因为迭代器只能往前走一遍。 需要多次遍历就必须用列表推导式。 
gen = (x for x in [1, 2, 3])
list(gen)      # [1, 2, 3]
list(gen)      # []       ← 空了

lst = [x for x in [1, 2, 3]]
list(lst)      # [1, 2, 3]
list(lst)      # [1, 2, 3]  ← 列表可以反复遍历

官方还说明了一个求值时机的细节：最左侧 for 子句里的可迭代对象表达式会立即求值， 所以它抛的错会立刻出现，而不是等到第一次取值：

(x ** 2 for x in nonexistent_iterable)
# NameError: name 'nonexistent_iterable' is not defined   ← 定义时就报错

iterator = (nonexistent_value for x in range(10))     # 这行不报错
list(iterator)                                        # 取值时才报错

4.6 内置函数：把循环换成一次调用

函数作用替代了什么循环
len(x)元素个数数一遍
sum(it, start=0)求和total = 0; for ...: total += x
max(it, key=) / min(it, key=)最大/最小，可按 key 比较「先设第一个为最大，然后逐个比」
sorted(it, key=, reverse=)返回新的排序列表手写排序
any(it)有一个为真就 True「找到就 break」
all(it)全部为真才 True「遇到假的就 break」
enumerate(it, start=0)同时给出序号和值range(len(...)) 取下标
zip(*its)多序列按位配对手写双下标
reversed(it)逆序迭代倒着数索引
abs(x) / round(x, n)绝对值 / 四舍五入—
filter(f, it) / map(f, it)过滤 / 逐项变换推导式（通常推导式更好读）
 
# sum：官方签名是 sum(iterable, /, start=0)
sum([12800, 3400, 21000])                     # 37200
sum(n["浏览"] for n in articles)               # 用生成器，省内存

# max / min：可以传可迭代对象，也可以传多个参数
max([1, 5, 3])                                # 5
max(1, 5, 3)                                  # 5
max(articles, key=lambda a: a["浏览"])          # 浏览量最高的那条

# any / all：官方定义就是短路的循环
any(n["浏览"] > 20000 for n in articles)       # 有爆款吗
all(n.get("来源") for n in articles)           # 每条都有来源吗

# 官方给出的 any / all 等价实现
def any(iterable):
    for element in iterable:
        if element:
            return True
    return False

def all(iterable):
    for element in iterable:
        if not element:
            return False
    return True
空序列的边界：官方明确写了 —— all() 在可迭代对象为空时返回 True，any() 为空时返回 False。 所以「每条新闻都有来源吗」对空列表会回答「是」，这通常在逻辑上会让人意外一点。

4.7 sorted(key=...)：排序的核心机制

官方签名：sorted(iterable, /, *, key=None, reverse=False)；返回新列表，不动原对象。 key 是一个单参数函数，用来从每个元素中提取「比较键」—— 每个元素的键只算一次，然后用于整个排序过程。 

titles = ["AI 写稿", "县级融媒体的三年", "算法"]
sorted(titles, key=len)                  # ['算法', 'AI 写稿', '县级融媒体的三年']
sorted(titles, key=len, reverse=True)    # 从长到短

# 按字典的某个字段排序
articles = [
    {"标题": "AI 写稿", "浏览": 12800},
    {"标题": "县级融媒体", "浏览": 3400},
    {"标题": "算法争议", "浏览": 21000},
]
sorted(articles, key=lambda a: a["浏览"])                    # 升序
sorted(articles, key=lambda a: a["浏览"], reverse=True)      # 降序

# 多级排序：key 返回元组，先比第一个，相同再比第二个
sorted(articles, key=lambda a: (-a["浏览"], a["标题"]))

# 不区分大小写排序
words = ["Apple", "banana", "Cherry"]
sorted(words)                 # ['Apple', 'Cherry', 'banana']  按码位，大写在前
sorted(words, key=str.lower)  # ['Apple', 'banana', 'Cherry']  按字母序

# key 也能用内置函数名或其他函数对象
sorted(["12", "3", "105"], key=int)      # ['3', '12', '105']

官方 FAQ 里讲的「施瓦茨变换」（用一个映射出来的「排序值」来排序）在 Python 里就用 key= 实现： Isorted.sort(key=lambda s: int(s[10:15]))。这是官方点名的推荐做法。

4.8 lambda 与它的循环陷阱

官方定义：「lambda 关键字用于创建小巧的匿名函数……在语法上，匿名函数只能是单个表达式。 在语义上，它只是常规函数定义的语法糖。」 

add = lambda a, b: a + b
add(1, 2)          # 3

# 官方示例：用作排序键
pairs = [(1, 'one'), (2, 'two'), (3, 'three'), (4, 'four')]
pairs.sort(key=lambda pair: pair[1])
pairs
# [(4, 'four'), (1, 'one'), (3, 'three'), (2, 'two')]

然后是那个经典陷阱。官方 FAQ 专门为它写了一个条目：「为什么在循环中定义的参数各异的 lambda 都返回相同的结果？」

# ❌ 错误
squares = []
for x in range(5):
    squares.append(lambda: x**2)

squares[2]()      # 16    ← 期望是 4
squares[4]()      # 16    ← 期望是 16

# 官方解释原文：
# 「这是因为 x 不是 lambda 表达式的局部变量，而是定义于外部作用域中，
#   并且它会在【调用 lambda 表达式时】被访问 —— 而不是在定义时。
#   在循环结束时，x 的值为 4，所以此时所有函数都将返回 4**2，即 16。」
#
# 还能验证：改掉 x，之前建的 lambda 结果也变
x = 8
squares[2]()      # 64
# ✅ 修复：用默认参数把当前值"绑"进去
squares = []
for x in range(5):
    squares.append(lambda n=x: n**2)

squares[2]()      # 4
squares[4]()      # 16

# 官方补充：「上述表现并不是 lambda 所特有的，常规的函数也同样适用。」

原因：默认参数在函数定义时求值（这条规则和 函数 · 可变默认参数是同一个机制）。 n=x 把当时 x 的值复制进去，之后 x 再怎么变都不影响。

5 · 应用场景

场景一：一次做完新闻数据的清洗、筛选与派生字段

raw = [
    {"标题": "  AI 写稿工具上线 - XX新闻网 ", "浏览": "12800", "来源": "科技日报社", "标签": ["AI", "产品"]},
    {"标题": "算法推荐争议调查｜独家",       "浏览": "21000", "来源": "新闻战线",   "标签": ["AI", "算法"]},
    {"标题": "县级融媒体三周年",             "浏览": "3400",  "来源": "新闻战线杂志", "标签": ["基层"]},
    {"标题": "AI 版权第一案",                "浏览": "9600",  "来源": "法治日报",   "标签": ["AI", "版权"]},
]

SOURCE_MAP = {"科技日报社": "科技日报", "新闻战线杂志": "新闻战线"}

# 1. 清洗 + 类型转换 + 来源归一：一个推导式 + 一个辅助函数
def clean(t):
    t = (t or "").strip()
    for sep in (" - ", "｜"):
        if sep in t:
            t = t.split(sep)[0]
    return t.strip()

news = [
    {
        "标题": clean(a["标题"]),
        "浏览": int(a["浏览"]),                                  # 字符串转整数
        "来源": SOURCE_MAP.get(a["来源"], a["来源"]),
        "标签": a.get("标签", []),
    }
    for a in raw
]

# 2. 筛选：只看 AI 相关
ai_news = [n for n in news if "AI" in n["标签"]]
print(len(ai_news))          # 3

# 3. 派生字段：用字典推导式加一列
level = {n["标题"]: ("爆款" if n["浏览"] >= 10000 else "常规") for n in news}
print(level)
# {'AI 写稿工具上线': '爆款', '算法推荐争议调查': '爆款',
#  '县级融媒体三周年': '常规', 'AI 版权第一案': '常规'}

# 4. 汇总：sum / max / any 替代手写循环
print("总浏览：", sum(n["浏览"] for n in news))          # 46800
print("最高：", max(news, key=lambda n: n["浏览"])["标题"])   # 算法推荐争议调查
print("有爆款：", any(n["浏览"] >= 20000 for n in news))      # True
print("全有来源：", all(n["来源"] for n in news))             # True

# 5. 去重 + 排序：集合推导式
print(sorted({n["来源"] for n in news}))               # ['news战线'...] 实际是按码位排序

# 6. 多级排序：按浏览量降序，同量按标题
for n in sorted(news, key=lambda n: (-n["浏览"], n["标题"])):
    print(f'{n["浏览"]:>6}  {n["标题"]}')
#  21000  算法推荐争议调查
#  12800  AI 写稿工具上线
#   9600  AI 版权第一案
#   3400  县级融媒体三周年
整段代码里没有一处手写累加循环： 清洗用推导式，筛选用推导式，派生字段用字典推导式，去重用集合推导式， 汇总用 sum / max / any / all，排序用 sorted(key=)。 这就是「写得更少做得更多」的实际样子。

场景二：大文件逐行过滤 —— 这里必须用生成器表达式

从几万行的新闻日志里筛出含特定关键词的行，再用 sum 统计。 如果先造一个列表，内存会一下涨上去。 

def iter_lines(path):
    """逐行产出文件内容（不一次性读进内存）。"""
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip("\n")

# 生成器链：每一步都只处理一行，不堆积
KEYWORDS = ("AI", "算法")

hit_count = sum(
    1
    for line in iter_lines("news.log")
    if any(kw in line for kw in KEYWORDS)
)
print("命中行数：", hit_count)

# 只要前 10 条命中样本（用 islice 截断，不会把全文件跑完）
from itertools import islice

samples = list(islice(
    (line for line in iter_lines("news.log") if any(kw in line for kw in KEYWORDS)),
    10,
))
print(len(samples))

# 需要多次使用这份结果时，才落地成列表
hit_lines = [line for line in iter_lines("news.log") if any(kw in line for kw in KEYWORDS)]
print(len(hit_lines))       # 列表，可以反复遍历
print(sum(len(l) for l in hit_lines))
需求用哪个原因
结果只消费一次（求和、计数、写文件）生成器表达式 (...)不占内存，边算边丢
结果要多次遍历、要索引、要 len()列表推导式 [...]列表支持反复遍历
需要去重集合推导式 {...}自动去重，成员检查快
要建「键→值」的映射表字典推导式 {k: v ...}直接产出字典

6 · 概念辨析

辨析 1：推导式什么时候不该用

# ❌ 一个推导式塞三件事：读起来要来回扫
result = [
    n["标题"].strip().split(" - ")[0].replace("｜", "")
    for n in news
    if n.get("浏览", 0) > 1000
    if n.get("来源") in SOURCE_MAP
    if len(n.get("标签", [])) >= 1
]

# ✅ 拆开：清洗、筛选、取值各司其职
def clean_title(t):
    t = (t or "").strip().split(" - ")[0]
    return t.replace("｜", "").strip()

qualified = [
    n for n in news
    if n.get("浏览", 0) > 1000 and n.get("来源") in SOURCE_MAP and n.get("标签")
]
result = [clean_title(n["标题"]) for n in qualified]

# ❌ 推导式里做副作用（打印、写文件、改外部变量）
[print(n["标题"]) for n in news]        # 能跑，但这是滥用
[log.append(n) for n in news]           # 副作用藏在推导式里，非常难查

# ✅ 副作用用循环
for n in news:
    print(n["标题"])
一条实用判断标准：推导式里的表达式超过一行、或者写不进去一个 if 表达式的复杂度，就别用它。 官方在讲「如何让程序更快」时说得很清楚： 「相较于试图对全部代码铺开做微观优化，优化算法可以产出更大的收益」、「抽象往往会造成中间层……应该避免过度的抽象」。 可读性优先于行数少。

辨析 2：生成器表达式 vs 列表推导式（括号不是小事）

# 方括号 = 列表（立刻算完，占内存）
lst = [x * 2 for x in range(1_000_000)]
len(lst)          # 1000000
lst[0]            # 0            可以索引
lst[:3]           # [0, 2, 4]    可以切片'
list(lst)         # 再遍历一遍也行

# 圆括号 = 生成器（不算，随用随算）
gen = (x * 2 for x in range(1_000_000))
len(gen)          # TypeError: object of type 'generator' has no len()
gen[0]            # TypeError: 'generator' object is not subscriptable
next(gen)         # 0            只能一个一个取
list(gen)         # 消费掉，之后 gen 就空了
[...] 列表推导式(...) 生成器表达式
求值时机立刻全部算完取一个算一个（惰性）
内存随数据量线性增长基本恒定（只存算法）
能否重复遍历可以不行，只能一遍
支持 len / 索引 / 切片可以都不行
适合结果要反复用、要按位置访问只做一次汇总 / 流式处理大数据

辨析 3：lambda 的循环变量陷阱

# ❌ 全返回 16
funcs = [lambda: x**2 for x in range(5)]
[f() for f in funcs]        # [16, 16, 16, 16, 16]

# ✅ 默认参数绑定当前值
funcs = [lambda n=x: n**2 for x in range(5)]
[f() for f in funcs]        # [0, 1, 4, 9, 16]

# ✅ 或者用 functools.partial / 定义一个真正的函数
def make_square(n):
    def sq():
        return n ** 2
    return sq

funcs = [make_square(x) for x in range(5)]
[f() for f in funcs]        # [0, 1, 4, 9, 16]

官方解释的关键句：「它会在调用 lambda 表达式时被访问 —— 而不是在定义时。」 所以循环结束时的 x 值（4）决定了所有函数的结果。 官方还强调：「上述表现并不是 lambda 所特有的，常规的函数也同样适用。」

辨析 4：key= 要传函数，不能传值

articles = [{"浏览": 100}, {"浏览": 300}, {"浏览": 200}]

# ❌ 写成值：不报错，但结果没有意义
sorted(articles, key="浏览")     # '浏览' 是字符串，不能调用 → 实际会报 TypeError

# ⚠️ 更隐蔽的一种：key 传了个常函数
sorted(articles, key=lambda a: 0)    # 所有键都是 0，顺序不变（稳定性保证）

# ✅ 正确：传一个「从元素取出比较键」的函数
sorted(articles, key=lambda a: a["浏览"])

# ✅ 类型错误的对策：先把字符串转成数字，再排
raw = [{"浏览": "12800"}, {"浏览": "3400"}]
sorted(raw, key=lambda a: int(a["浏览"]))     # 数字序
sorted(raw, key=lambda a: a["浏览"])          # 字符串序（"3400" > "12800"，反了！）
排序前一定要确认类型。 "3400" > "12800" 是 True（字符串按字典序逐位比）， 所以直接对字符串浏览量排序，结果会乱七八糟。这是 字符串和排序交叉处的经典坑。

辨析 5：sum 的 start 参数与类型

sum([1, 2, 3])                  # 6
sum([1, 2, 3], start=100)       # 106    默认 start 是 0

# ⚠️ sum 不能连接字符串（官方在讲 join 时说得很明确）
sum(["a", "b"], start="")     # TypeError: sum() can't sum strings
"".join(["a", "b"])           # 'ab'   ← 拼字符串用 join

# ⚠️ sum 对布尔值很好用（True 就是 1）
sum(n["浏览"] > 10000 for n in articles)     # 爆款条数
sum(1 for n in articles if "AI" in n["标签"])  # 计数，推荐让意图更清楚

# ⚠️ 空列表的边界
sum([])          # 0
max([])          # ValueError: max() arg is an empty sequence
max([], default=0)   # 0   ← 用 default 参数（3.4+）
any([])          # False
all([])          # True   ← 注意！空序列 all 为 True

辨析 6：推导式的变量作用域

# 列表推导式有自己的作用域，循环变量不会泄漏到外面
x = "外部的 x"
squares = [x for x in range(3)]
print(x)         # 外部的 x   ← 没被覆盖

# 但普通 for 循环会泄漏（详见 循环 那份资料）
x = "外部的 x"
for x in range(3):
    pass
print(x)         # 2   ← 被覆盖了！

# 推导式内部可以用外部变量
threshold = 10000
hot = [n for n in news if n["浏览"] > threshold]   # ✅ 能读到 threshold

# 推导式里给外部变量赋值？做不到 —— 推导式只能写表达式
# [total += n["浏览"] for n in news]     # SyntaxError

这就是为什么可以放心地用 n、a 这类短名字写推导式 —— 它不会污染外面的命名空间。但普通 for 循环的变量会泄漏，两者不一样。

7 · 自测问题

Q1：把 result = []; for t in titles: if len(t) > 5: result.append(t.upper()) 改写成推导式。
result = [t.upper() for t in titles if len(t) > 5]。 结构是「表达式 + for 子句 + if 子句」，官方说明这个顺序不能颠倒。
Q2：[x**2 for x in range(10)] 和 (x**2 for x in range(10)) 有什么区别？
前者立刻造出完整列表，占内存、可重复遍历、可以索引和 len()； 后者是生成器迭代器，惰性求值、内存几乎不随数据量增长，但只能消费一次， 且不支持 len / 索引 / 切片。
Q3：为什么 [x, x**2 for x in range(6)] 会报错？
元组表达式必须加圆括号，否则语法错误。官方给出的报错文本是 SyntaxError: did you forget parentheses around the comprehension target?， 正确写法 [(x, x**2) for x in range(6)]。
Q4：funcs = [lambda: x**2 for x in range(5)]，调用每个函数得到什么？为什么？
全部返回 16。官方解释：x 不是 lambda 的局部变量，而是定义于外部作用域， 且在调用时才被访问；循环结束时 x 为 4，所以所有函数都算 4**2。 修法：lambda n=x: n**2。
Q5：sorted(articles, key=lambda a: a["浏览"]) 里的 key 是干什么的？为什么不能写 key=a["浏览"]？
key 是一个单参数函数，用来从每个元素中提取比较键（每个元素的键只算一次）。 它必须是可调用的；写 a["浏览"] 传的是某个具体的值，不是函数，会报错。
Q6：any([]) 和 all([]) 分别是什么？
any([]) 是 False，all([]) 是 True。 官方明确：「all() 在可迭代对象为空时返回 True」、 「any() …… 如果可迭代对象为空，返回 False」。
Q7：什么时候不该用推导式？
三件事都该避开：（1）推导式里塞了多层筛选和复杂表达式，读起来要来回扫； （2）在推导式里做副作用（print、append 到外部列表、写文件）； （3）嵌套超过两层。此时改用普通循环 + 辅助函数，可读性更好。
