1 · 个人理解（先说人话）

条件判断就是让程序做选择。翻译成中文就是「如果……就……，否则……就……」。 

if 浏览量 > 10000:
    标记为"爆款"
else:
    标记为"普通稿"

没了。真的就这么简单。所有的复杂判断都是这几句话套起来的。

你需要注意的其实只有两件事：

  1. 缩进就是语法。Python 用缩进表示「这几行属于 if 里面」。少一个空格、多一个空格，程序的意思就变了，甚至直接报错。
  2. 「真」和「假」的范围比你想象的大。不只是 True / False —— 0、空字符串 ""、空列表 []、None 全都被当成「假」。
views = 0
if views:
    print("有人看过")
else:
    print("浏览量是 0")     # ← 走这里，因为 0 是"假"

titles = []
if not titles:
    print("一条标题都没有")   # ← 走这里，空列表是"假"
一句话记住：if 后面不需要写 == True。 你只需要问「这个东西本身算不算有」—— 空的、零的、没有的，都算没有。

2 · 学习目标

学完这份资料，你应该能：

  1. 写出带 if / elif / else 的多分支判断，并说清 elif 与连续写多个 if 的区别；
  2. 区分 = 与 ==，看到 if x = 1: 能立刻指出错误；
  3. 背出「哪些值算假」，并能用这个规则写出简洁的判断（如 if not titles:）；
  4. 用 and / or / not 组合条件，并解释为什么它们返回的是操作数而不是 True/False；
  5. 使用链式比较 0 < x < 100，并说明它和 0 < x and x < 100 的区别；
  6. 用 in / not in 判断成员关系，并知道它对字典是检查键。

4 · 结构化解释

4.1 定义

条件判断：根据条件的真假决定执行哪一段代码。Python 里用 if 语句实现。 官方教程指出：「可有零个或多个 elif 部分，else 部分也是可选的。关键字 elif 是 else if 的缩写，用于避免过多的缩进。」

4.2 最小模型：三条分支的一套骨架

views = 12800

if views >= 100000:
    level = "现象级"
elif views >= 10000:
    level = "爆款"
elif views >= 1000:
    level = "正常"
else:
    level = "冷启动"

print(level)     # 爆款

执行顺序是从上往下，第一个为真的分支执行完就跳出整个 if 结构， 后面的分支连条件都不会求值。这一点决定了 elif 和多个 if 的本质区别（见辨析 1）。 

# 等价于官方教程里的例子
x = 42
if x < 0:
    print('Negative changed to zero')
elif x == 0:
    print('Zero')
elif x == 1:
    print('Single')
else:
    print('More')
# More

4.3 类比

概念类比说明
if门口第一个保安，只检查一件事符合就放行，不符合交给下一个
elif下一个保安，前面放行了就不查了只有前面全部不合格才轮到它
else谁都不管，直接进兜底，前面全部不合格时执行
缩进「这句话属于哪个保安管的」缩进一样才是同一层，是语法不是排版
真值规则「有没有东西」空的、零的、没有的 → 假
and两个条件都要满足返回第一个假值，或最后一个值
or满足一个就行返回第一个真值，或最后一个值
链式比较「在 0 到 100 之间」0 < x < 100，比写两遍 x 清爽

4.4 缩进就是语法

# ✅ 正确
if views > 10000:
    print("爆款")
    print("要重点分析")

# ❌ IndentationError: expected an indented block
if views > 10000:
print("爆款")

# ❌ IndentationError: unindent does not match any outer indentation level
if views > 10000:
    print("爆款")
      print("要重点分析")     # 多缩进了两个空格

# ⚠️ 不报错，但意思完全变了
if views > 10000:
    print("爆款")
print("要重点分析")          # ← 这行在 if 外面，永远会执行！
最后那种写法不报错，但逻辑是错的 —— 这是最难查的一类 bug。 做法：编辑器设置 tab 转 4 个空格，不要混用 tab 和空格。 PEP 8 明确要求「缩进用 4 个空格，不要用制表符」，理由是制表符在不同环境下宽度不一致，会引起混乱。

4.5 真值测试：哪些东西算「假」

官方文档「真值测试」一节给的默认规则是：一个对象被认为是「真」的，除非它的类定义了返回 False 的 __bool__() 方法，或定义了返回零的 __len__() 方法。

官方列出的内置假值清单：

类别具体值
定义为假的常量None、False
任何数值类型的零0、0.0、0j、Decimal(0)、Fraction(0, 1)
空序列与空集合''、()、[]、{}、set()、range(0)
 
# 用 bool() 验证
bool(None)      # False
bool(0)         # False
bool(0.0)       # False
bool("")        # False
bool([])        # False
bool({})        # False
bool(set())     # False

bool("0")       # True   ← 字符串 "0" 不是空字符串，所以是真！
bool([0])       # True   ← 列表里有一个元素，非空
bool(-1)        # True   ← 非零即真
bool(" ")       # True   ← 一个空格也是字符
bool("0") 是 True，bool("False") 也是 True。 从文件或输入框读到的「0」「False」「否」全都是非空字符串，全都被当成真。 要判断字符串表示的真假，必须先转换：if value.strip().lower() in ("0", "false", "no", "否"): 
# 实战写法：利用真值规则
titles = []
if not titles:                  # 比 if len(titles) == 0: 更 Pythonic
    print("没有数据")

name = ""
if name:                        # 有内容才处理
    print(name)

count = 0
if count:
    print("有计数")
else:
    print("计数为 0")            # ← 走这里

4.6 布尔运算：and / or / not

官方文档的关键提醒：「具有布尔结果的操作和内置函数，对假返回 0 或 False， 对真返回 1 或 True …… 重要例外：布尔运算 or 和 and 总是返回其操作数之一。」 

# and：从左到右求值，返回第一个"假"的值；全是真则返回最后一个
0 and "x"         # 0
"a" and ""        # ""
"a" and "b"       # "b"

# or：从左到右求值，返回第一个"真"的值；全是假则返回最后一个
0 or "默认"        # "默认"
"a" or "b"        # "a"
"" or 0 or None   # None

# not：永远是布尔值
not 0             # True
not "x"           # False
# 常见用法一：给默认值
src = ""
src = src or "未标注"
print(src)        # 未标注

# 常见用法二：短路保护，避免报错
data = []
if data and data[0] == "x":      # data 为空时不会走到 data[0]，不会 IndexError
    print("第一项是 x")

# 如果写成 data[0] == "x" and data，空列表会先崩

# 常见用法三：链式提供默认值
name = user_input or fallback or "匿名"
or 给默认值有坑：0 or 5 得到 5，"" or "x" 得到 "x"。 如果 0 本身是有意义的合法值（比如「浏览量是 0」），用 or 会把它换成默认值，造成数据错误。 这种情况应该用 x if x is not None else 默认值。

4.7 链式比较

官方原文：「比较可以任意链式连接；例如 x < y <= z 等价于 x < y and y <= z， 不同之处在于 y 只被求值一次（但两种情况下，当发现 x < y 为假时，z 都完全不会被求值）。」 

x = 50
0 < x < 100          # True      等价于 0 < x and x < 100
0 < x <= 50         # True
0 < x > 100         # False     实际是 0 < x and x > 100

# 这为什么重要：y 只求值一次，函数调用不会跑两遍
def expensive():
    print("算了一次")
    return 50

0 < expensive() < 100     # 只打印一次「算了一次」

# 写成这样就会算两遍
0 < expensive() and expensive() < 100

实际写代码时，链式比较的可读性优势更明显：if 1000 <= views < 10000: 比 if views >= 1000 and views < 10000: 更容易一眼看懂。

4.8 in：成员关系判断

官方说明：「另外两个具有相同语法优先级的运算符 in 和 not in， 由可迭代或实现了 __contains__() 方法的类型所支持。」 

# 字符串：子串
"AI" in "AI 重塑新闻业"        # True

# 列表：元素
"科技日报" in ["科技日报", "新闻战线"]    # True
12800 in [12800, 3400]                  # True

# 字典：检查的是键，不是值
news = {"标题": "AI 重塑新闻业", "来源": "科技日报"}
"来源" in news                  # True
"科技日报" in news              # False
"科技日报" in news.values()     # True

# 元组、集合同样支持
2 in (1, 2, 3)                 # True
2 in {1, 2, 3}                 # True

# not in
"z" not in "abc"               # True
# 实战：多条件筛选新闻
tags = ["AI", "算法"]
title = "AI 算法推荐机制的争议"

if "AI" in tags or "算法" in tags:
    print("命中关注标签")

# 判断多个字符串前缀，用元组（startswith 支持元组参数）
url = "https://x.com/news"
if url.startswith(("http://", "https://")):
    print("是完整链接")

# 判断取值是否在允许集合里
SOURCE_OK = {"科技日报", "新闻战线", "法治日报"}
src = "科技日报"
if src in SOURCE_OK:
    print("来源已核对")

4.9 is 与 == 在条件里的选择

news = None

if news is None:              # ✅ 判断 None 用 is（PEP 8 推荐）
    print("没数据")

if news == None:              # ⚠️ 能跑但不推荐
    print("没数据")

# == 判断值相等，is 判断是不是同一个对象
a = [1, 2, 3]
b = [1, 2, 3]
a == b        # True
a is b        # False

# 官方说明：is 和 is not 的行为无法被自定义，可应用于任意两个对象，
# 且从不会引发异常；== 对某些对象类型（如类对象）等价于 is

5 · 应用场景

场景一：给新闻自动分级并打标签

def classify(news: dict) -> str:
    """按浏览量和来源给一条新闻分级。"""
    views = news.get("浏览", 0)
    src = news.get("来源", "")

    # 链式比较 + 真值判断的组合
    if not src:
        return "数据不全"
    if views >= 100000:
        return "现象级"
    if 10000 <= views < 100000:
        return "爆款"
    if 1000 <= views < 10000:
        return "常规"
    return "冷启动"

articles = [
    {"标题": "AI 写稿工具上线", "浏览": 12800, "来源": "科技日报"},
    {"标题": "算法推荐争议调查", "浏览": 210000, "来源": "新闻战线"},
    {"标题": "某地简讯", "浏览": 320, "来源": "某地方台"},
    {"标题": "无来源稿件", "浏览": 5000},
]

for a in articles:
    a["级别"] = classify(a)
    print(f'{a["标题"]:<12} → {a["级别"]}')
# AI 写稿工具上线 → 爆款
# 算法推荐争议调查 → 现象级
# 某地简讯       → 冷启动
# 无来源稿件     → 数据不全

注意 classify() 里用了连续的 if + return：只要执行到 return 函数就结束了， 所以不需要写一堆 elif。这种「卫语句」写法比层层嵌套的 else 更好读。

场景二：判断一条稿件是否值得跟进（多条件组合）

def worth_following(news: dict) -> tuple:
    """返回 (是否跟进, 原因)。"""
    views = news.get("浏览", 0)
    tags = news.get("标签", [])
    src = news.get("来源", "").strip()

    # 用 and 短路，避免取到不存在的键
    if views >= 10000 and "AI" in tags:
        return True, "高热度 AI 选题"
    if "AI" in tags and src in {"科技日报", "新闻战线"}:
        return True, "核心来源的 AI 报道"
    if not tags:
        return False, "无标签，需人工判断"
    if views < 1000:
        return False, "热度不足"
    return False, "不满足跟进条件"

cases = [
    {"标题": "A", "浏览": 21000, "标签": ["AI"], "来源": "科技日报"},
    {"标题": "B", "浏览": 500,  "标签": [], "来源": "某地方台"},
    {"标题": "C", "浏览": 8000, "标签": ["AI"], "来源": "新闻战线"},
    {"标题": "D", "浏览": 300,  "标签": ["基层"], "来源": "某地方台"},
]

for c in cases:
    ok, why = worth_following(c)
    print(f'{c["标题"]}: {"跟进" if ok else "跳过"} —— {why}')
# A: 跟进 —— 高热度 AI 选题
# B: 跳过 —— 无标签，需人工判断
# C: 跟进 —— 核心来源的 AI 报道
# D: 跳过 —— 热度不足
判断顺序是有讲究的。把「数据不全 / 无标签」这类前置检查放在最前面， 后面就可以放心地用 views >= 10000 这类比较，不用再防御性判断。 这就是「卫语句优先」的实践价值。

6 · 概念辨析

辨析 1：elif vs 多个独立的 if

views = 12800

# elif：命中一个就跳出，后面的条件不求值
if views >= 100000:
    print("现象级")
elif views >= 10000:
    print("爆款")          # ← 只打印这一行
elif views >= 1000:
    print("常规")

# 多个 if：每个条件都要单独检查，可能同时命中
if views >= 100000:
    print("现象级")
if views >= 10000:
    print("爆款")          # ← 也打印
if views >= 1000:
    print("常规")          # ← 还打印！

互斥的等级判断要用 elif；互相独立的标记（比如「同时记录是否爆款、是否含 AI」）才用多个 if。

辨析 2：= vs ==

views = 12800         # 赋值：把 12800 贴到 views 上

if views == 12800:    # 比较：问「views 是 12800 吗」
    print("命中")

if views = 12800:     # ❌ SyntaxError: invalid syntax.
    print("命中")     #    Python 3 会直接报语法错，这其实是件好事
在 C / Java 里 if (x = 1) 是合法但错误的写法（会把 1 赋给 x，然后判断 1 为真）， 极难查。Python 3 直接禁止了这种语法，所以这个坑在 Python 里报错很响，不用担心。 真正要小心的是：把 == 写成 = 之后，很多编辑器会自动「修正」成语法错误提示，反而容易让人没看明白问题出在哪。

辨析 3：if x: vs if x == True: vs if x is True:

x = 1

if x:               # True  ← 推荐：靠真值测试
if x == True:       # True  ← 相当于 x == 1，因为 True == 1
if x is True:       # False ← x 是整数 1，不是 True 这个单例对象

x = "0"
if x:               # True  ← 非空字符串
if x == True:       # False
# ⚠️ 最坑的一种写法
flag = 1
if flag is True:
    print("不会打印")     # 因为 1 is True 为 False（虽然 1 == True 为 True）
推荐只用 if x:（真值测试）和 if x is None:（判 None）。 别写 == True 和 is True，除非你非常确定自己在干什么。

辨析 4：and / or 返回的是操作数，不是布尔值

# 这个特性很有用，但也很容易误用
result = "" or "默认标题"
type(result)        # <class 'str'>  ← 不是 bool！

# 误用：以为 or 的结果一定是布尔值
count = 0
value = count or "没有数据"
print(value)        # "没有数据"  ← 0 被吃掉了

# 想要「只把 None 当缺失」，应该写
count = 0
value = count if count is not None else "没有数据"
print(value)        # 0  ← 正确保留

辨析 5：in 对字典检查键；对字符串检查子串

news = {"标题": "AI 重塑新闻业", "来源": "科技日报"}

"来源" in news               # True   检查键
"科技日报" in news           # False  值不参与检查

s = "AI 重塑新闻业"
"AI" in s                    # True   子串检查
"媒体" in s                  # False

lst = ["AI", "算法"]
"AI" in lst                  # True   元素检查
["AI"] in lst                # False  列表不等于元素

# 想检查复合条件，用 all() / any()
tags = ["AI", "算法", "推荐"]
all(t in tags for t in ["AI", "算法"])    # True
any(t in tags for t in ["区块链", "AI"])  # True

辨析 6：嵌套太深怎么办 —— 卫语句与合并条件

# ❌ 三层嵌套，读起来要上下扫
def check(a):
    if a:
        if a.get("浏览"):
            if a["浏览"] > 10000:
                return "爆款"
            else:
                return "普通"
        else:
            return "无浏览量"
    else:
        return "无数据"

# ✅ 卫语句：不符合条件的先返回，主逻辑保持在最外层
def check(a):
    if not a:
        return "无数据"
    if not a.get("浏览"):
        return "无浏览量"
    if a["浏览"] > 10000:
        return "爆款"
    return "普通"

# ✅ 合并条件：能用 and 表达的就别嵌套
if a and a.get("浏览") and a["浏览"] > 10000:
    ...
# 更简洁的写法（Python 3.8+ 海象运算符，或先取变量）
views = (a or {}).get("浏览", 0)
if views > 10000:
    ...

PEP 8 建议缩进用 4 个空格，一个现实的好处是：嵌套三层以后右半边就没位置了， 这会逼着你早点用卫语句把代码拉平。

7 · 自测问题

Q1：bool("0") 和 bool(0) 分别是多少？
True 和 False。"0" 是非空字符串，属于「真」； 0 是数值零，属于官方列出的「假」值。
Q2：if x = 1: 会发生什么？
SyntaxError: invalid syntax。Python 3 里赋值语句不能出现在条件表达式中， 比较要用 ==。这是 Python 比 C / Java 安全的地方。
Q3：if a: ... elif b: ... elif c: ... 中如果 a 和 b 都为真，会打印几次？
一次。elif 只有在前面的条件全部为假时才会被求值，命中第一个为真的分支后就跳出整个结构。
Q4：0 or "默认" 的结果是什么？类型是什么？
"默认"，类型是 str。官方文档说明：布尔运算 or 和 and 总是返回其操作数之一，而不是把结果转成 True / False。
Q5：0 < x < 100 和 0 < x and x < 100 有什么区别？
结果相同。区别在于链式比较中 x 只求值一次（官方原文：except that y is evaluated only once）。 当 x 是函数调用时，链式写法只调用一次。
Q6：news = {"标题": "..."}，"标题" in news 检查的是什么？
检查键。返回 True。要检查值必须写 "..." in news.values()。
Q7：想判断一个变量是不是 None，应该怎么写？
if x is None:。PEP 8 推荐对单例对象 None 用 is / is not。 if not x: 会把 0、""、[] 也一起算进去，语义不同。
